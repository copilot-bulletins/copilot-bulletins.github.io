Monthly (Long) #7 · September 2026 · Admins Edition

🎯 This edition's thread

September centered on enterprise control. GitHub expanded managed settings, agent permissions, and content exclusions, giving administrators centralized guardrails that users and workspaces cannot weaken. In parallel, adoption visibility deepened: the impact dashboard, usage metrics API, and OpenTelemetry support turn Copilot activity into measurable, auditable signals. Budget governance also matured with expiration dates and self-service increase requests. For administrators, the practical takeaway is clear: you now have finer-grained policy, security, and observability levers to scale Copilot responsibly—while a wave of model deprecations means model policies need review before mid-October.

🏆 Top 8 updates of the month

1. Enterprise-managed guardrails for agents go further

Administrators can now centrally control which agent operations are blocked, require approval, or proceed freely—covering shell commands, file reads/edits, and network domains. These managed restrictions can't be weakened by users, workspaces, or auto-approval, and support team-specific policies.

Sources:
→ Changelog: Enterprise managed permissions for GitHub Copilot agent operations
→ Changelog: Enterprise-managed settings support any default model
→ Changelog: Enterprise managed settings in product validator

2. Deeper adoption and usage visibility

The impact dashboard now shows feature engagement so you can see which experiences are widely adopted. The usage metrics API adds pull request review stages and VS Code agents, giving administrators richer, auditable signals to measure value and target enablement.

Sources:
→ Changelog: Copilot impact dashboard now shows feature engagement
→ Changelog: Usage metrics API adds pull request review stages
→ Changelog: Add VS Code agents to Copilot usage metrics

3. More control over Copilot budgets

You can now set an optional expiration date on individual user budgets, with automatic fallback to the next applicable budget. Members who hit their limit can request more budget in-flow, and you approve, adjust, or deny without leaving settings.

Sources:
→ Changelog: Set an expiration date for individual user budgets
→ Changelog: Copilot budget increase requests are generally available

4. Copilot code review investment accelerates

Copilot code review can now signal when a PR is ready and, with admin opt-in, approve it. New auto-resolution, analysis improvements, and more ways to request and configure reviews make automated review a governable part of your merge workflow.

Sources:
→ Changelog: Copilot code review can now approve pull requests
→ Changelog: Auto-resolution and analysis updates in Copilot code review
→ Changelog: Copilot code review: more ways to request and configure reviews

5. Content exclusions reach the Copilot app and CLI

The Copilot app and CLI now respect content exclusion policies set by enterprise, organization, and repository administrators. Excluded files won't be used as context, extending sensitive-code protection across agentic workflows for Business and Enterprise customers.

→ Changelog: Content exclusions generally available in Copilot app and CLI

6. A new default enablement policy for new features

A global default policy lets you decide how generally available Copilot features roll out to users. For a 28-day window you can configure it with no user impact, giving you time to align new-feature access with your governance posture before it takes effect.

→ Changelog: Default enablement of Copilot features for Copilot Business and Enterprise

7. Sandboxing to contain agent risk

Local sandboxing limits agent access to files, network, and credentials per project, reducing the impact of unintended commands. Combined with the enterprise-managed sandbox for JetBrains, administrators gain stronger containment for local and IDE agent sessions.

Sources:
→ Changelog: Local sandboxing in the GitHub Copilot app
→ Changelog: Enterprise-managed sandbox in Copilot for JetBrains

8. OpenTelemetry observability for Copilot agents

The Copilot app now supports OpenTelemetry through enterprise-managed settings, letting administrators stream agent activity to their monitoring tools. This brings Copilot into existing observability pipelines for auditing, performance analysis, and compliance.

→ Changelog: OpenTelemetry in the GitHub Copilot app
