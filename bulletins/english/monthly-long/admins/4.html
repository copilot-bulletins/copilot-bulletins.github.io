Monthly (Long) #4 · June 2026 · Admins Edition

🎯 This edition's thread

June's dominant theme for administrators was governance catching up with agentic development. With usage-based billing now live across all plans, GitHub shipped the controls to match: per-user credit budgets on cost centers, richer consumption and adoption data in reports and the metrics API, and the first real policy levers in enterprise-managed settings. Security and code review matured in parallel. For admins, the month is less about new features to try and more about the guardrails, visibility, and cost discipline needed to scale Copilot responsibly.

⚠️ Heads up

  • GPT-4.1 deprecated — Deprecated: June 1, 2026 — GPT-4.1 is retired across Copilot experiences; confirm your model availability policies point users to GPT-5.5.
  • GPT-5.2 and GPT-5.2-Codex deprecated — Deprecated: June 5, 2026 — Move workflows to GPT-5.5 and GPT-5.3-Codex (GPT-5.2 remains available in Copilot code review).
  • Upcoming deprecation of Opus 4.6 (fast) — Deprecated: June 29, 2026 — Enable Opus 4.8 (fast) in your model policies so users keep a fast Claude option.

🚀 Take action

  • Control Copilot spend by setting per-user AI credit budgets on cost centers so limits follow users as teams change.
  • Tighten client governance: disable automatic command approval ("yolo mode") and restrict plugin sources with enterprise plugin standards.
  • Connect spend to value by tracking the Copilot usage metrics dashboard and API across your teams.
  • Review your model availability policies so teams land on supported models before deprecations take effect.
  • Questions or need support? Reach out to your GitHub team, we're here to help.

🏆 Top 8 updates of the month

1. Usage-based billing goes live with per-user cost controls

Usage-based billing is now active for all Copilot plans, and admins gain finer spend control: a single per-user AI credit budget on a cost center applies to every member and follows them as teams change — no more managing thousands of individual budgets.

Sources:
→ Changelog: Updates to GitHub Copilot billing and plans
→ Changelog: Per-user AI credit budgets available for cost centers

2. Enterprise-managed settings gain real governance controls

Enterprise-managed settings added their first governance levers: admins can disable bypass-permissions ("yolo") mode and enforce strictKnownMarketplaces to control which plugins users install — across both VS Code and Copilot CLI. VS Code also gained enterprise-managed plugin distribution.

Sources:
→ Changelog: Enterprise-managed settings now support bypass permission controls
→ Changelog: Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI
→ Changelog: Enterprise-managed plugins in VS Code in public preview

3. Deeper visibility into consumption and adoption

Reporting improved materially: the usage metrics API now surfaces AI credits consumed per user, reports capture more active users via server-side telemetry, and enterprise and organization reports break down total merged pull requests by AI adoption phase — connecting spend to impact.

Sources:
→ Changelog: AI credits consumed per user now in the Copilot usage metrics API
→ Changelog: Copilot usage metrics now include more of your active users
→ Changelog: Track total merges by adoption phase in enterprise and organization reports

4. Copilot code review adds organization-level configuration

Code review became easier to govern: organizations can set runner controls (self-hosted or large runners), apply content exclusion, and remove custom-instruction limits. A new Medium analysis depth is now configurable org-wide, while CLI-based file tools cut review cost with no workflow change.

Sources:
→ Changelog: Copilot code review: New configurations and controls
→ Changelog: Copilot code review: Analysis depth and efficiency updates

5. Security validation extends to third-party agents

Code from third-party coding agents (including Claude and OpenAI Codex) now receives the same automatic validation as Copilot cloud agent — CodeQL analysis, dependency checks, and secret scanning before the pull request is finalized. Developers also gained a /security-review command in Copilot CLI.

Sources:
→ Changelog: Security validation for third-party coding agents
→ Changelog: Dedicated security review command now available in Copilot CLI

6. The GitHub Copilot app reaches general availability

The GitHub Copilot desktop app is now generally available for macOS, Windows, and Linux — a native home for agent-driven work with parallel sessions, cloud automations, and MCP support. It also added bring-your-own-key, giving admins a new managed surface to plan for.

Sources:
→ Changelog: GitHub Copilot app generally available
→ Changelog: GitHub Copilot app support for BYOK

7. New models reach general availability

Model choice expanded again: Claude Sonnet 5 and Claude Fable 5 are now generally available, and Microsoft's MAI-Code-1-Flash reached GA for Copilot Business and Enterprise. Review your model policies to decide which options to enable for your organization.

Sources:
→ Changelog: Claude Sonnet 5 is generally available for GitHub Copilot
→ Changelog: Claude Fable 5 is generally available for GitHub Copilot
→ Changelog: MAI-Code-1-Flash for Copilot Business and Copilot Enterprise

8. Copilot Memory adds enterprise governance

Copilot Memory now supports user-level preferences — communication style, tool stack, git conventions — for Copilot Business and Enterprise in public preview, with new admin controls for governance so organizations can adopt personalization while keeping oversight.

→ Changelog: Copilot Memory supports user preferences for Business, Enterprise
