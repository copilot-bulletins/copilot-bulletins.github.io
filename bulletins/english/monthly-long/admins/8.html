Monthly (Long) #8 · October 2026 · Admins Edition

🎯 This edition's thread

October shifted Copilot administration from managing seats to governing usage. Licensing, billing, and policy defaults now point toward budget-based control, with more settings managed centrally and enforced on every client.

Visibility improved alongside that control. Usage reporting now covers more tools, names internal customizations, and adds peer benchmarks. Agent execution gained stronger local guardrails. For admins, this is a good time to review default policies, managed settings, and budgets before the next round of features reaches your users.

⚠️ Heads up

  • Upcoming deprecation of selected GitHub Copilot models in mid-November — Deadline: November 16, 2026 — Claude Opus 4.8, Claude Opus 5 and GPT-5.6 Terra will be retired. Confirm the suggested alternatives are enabled in your model policies.
  • Update your IDE to restore agent activity in Copilot usage metrics — Action required — Agent activity from affected IDE versions is undercounted and cannot be backfilled. Roll out the fixed versions listed in the supported IDEs documentation as they ship.

🚀 Take action

  • Review your global default under AI Controls and check which features it now sets, using default availability of Copilot features
  • Decide whether to require sandboxing, fresh policy at startup, and approved plugins through enterprise managed settings
  • Set code review billing, maximum effort level, and approvals in Configuring code review by GitHub Copilot
  • Discuss the new licensing model with your account team after reading What's changing with GitHub Enterprise and Copilot billing
  • Questions or need support? Reach out to your GitHub team, we're here to help.

🏆 Top 8 updates of the month

1. Copilot is now included with GitHub Enterprise

Enterprises working with a GitHub or Microsoft account team can get Copilot included for every GitHub Enterprise licensed user. Admins manage usage against the enterprise budget, not seat counts. Copilot Business and Enterprise remain available, and self-serve availability is coming in stages.

→ Changelog: GitHub Enterprise now includes access to GitHub Copilot

2. Feature and model policies: global default enforced, now scriptable

From October 22 to 26, GitHub gradually applied the global default policy to unconfigured, generally available features. Explicit choices were kept. New REST endpoints let you read and update model policies for enterprises, enterprise teams, agent apps, and organizations.

Sources:
→ Changelog: Global default for Copilot features generally available
→ Changelog: Copilot model policy API for enterprise, orgs, and teams

3. Enterprise managed settings get stronger enforcement

Admins can force clients to fetch current policy at startup, require minimum client versions, and require or block plugins from approved marketplaces. A separate setting can attribute OpenTelemetry data to users. Each capture class is off by default.

Sources:
→ Changelog: Enterprise managed settings enforcement updates
→ Changelog: Repository plugin defaults and enterprise plugin controls generally available
→ Changelog: Client telemetry user attribution and configurable capture

4. Usage metrics API covers more tools and names internal customizations

A new totals_by_client array reports requests and tokens from tools such as OpenCode, Claude Code, and Codex. Reports now name your organization's skills, custom agents, and MCP servers instead of grouping them as "other", so you can track internal adoption.

Sources:
→ Changelog: Usage metrics API adds usage from tools like OpenCode
→ Changelog: Custom skills, agents, and MCP servers in usage metrics API

5. Benchmark adoption against industry peers

The Copilot impact dashboard adds an opt-in industry comparison. It compares agentic adoption and merge-rate leverage with peers filtered by company size and industry. Benchmarks are aggregated without identifying data, stay within the same region, and are deleted after 30 days.

→ Changelog: Industry comparisons in the Copilot impact dashboard

6. Copilot code review: billing controls, Max, and approvals

Organizations can bill code reviews to a cost center instead of member quotas and block reviews from external licenses. Max effort is in preview, and admins can cap its use. Approvals are generally available but off by default.

Sources:
→ Changelog: Copilot code review: New organization billing options and controls
→ Changelog: Copilot code review: Merge with confidence with Max and approvals
→ Changelog: Copilot code review: API support and new default effort level

7. Local sandboxing and assisted permissions are generally available

Local sandboxing limits filesystem, network, and credential access for agent commands in Copilot CLI, the app, and VS Code. You can enforce it through managed settings. Admins can also block "Allow All" and set the default permission mode.

Sources:
→ Changelog: Local sandboxing for GitHub Copilot now generally available
→ Changelog: GitHub Copilot assisted permissions generally available

8. AI-powered remediation and secret detection

Agentic autofix is generally available. It fixes code scanning alerts, reruns CodeQL to validate the fix, and opens a draft pull request. An enterprise policy controls access. A purpose-built model now handles AI-detected secret alerts at no extra cost for GHSP and GHAS customers.

Sources:
→ Changelog: Agentic autofix for code scanning alerts general availability
→ Changelog: Purpose-built model for leaked secret detection
