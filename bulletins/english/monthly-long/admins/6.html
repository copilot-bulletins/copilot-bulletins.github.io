Monthly (Long) #6 · August 2026 · Admins Edition

🎯 This edition's thread

August centered on governance and measurement. Enterprise managed settings matured into a real control plane — MCP allowlists, team-scoped policies, marketplace auto-updates, and JetBrains coverage — while the global model policy moved to general availability with staged enforcement. In parallel, new ROI and per-agent, per-model usage reporting turned Copilot spend into something you can trace and justify. For admins, the takeaway is concrete: you can now define guardrails once, delegate safely to teams, and prove value with data rather than assumption.

🏆 Top 7 updates of the month

1. Enterprise managed settings become a governance control plane

Managed settings gained the controls admins have been asking for: centrally approve or block MCP servers, target policies to specific enterprise teams with additive plugin and marketplace layers, and auto-update permitted plugin marketplaces. You define the floor once, then delegate safely without weakening guardrails.

Sources:
→ Changelog: MCP allowlists in enterprise managed settings
→ Changelog: Enterprise team specialization for managed settings
→ Changelog: Enterprise-managed settings now support autoUpdate for plugin marketplaces

2. Global model policy is generally available

Enforcement of the default model policy is rolling out gradually through September 1. Newly available and previously unconfigured models inherit the global policy, while open-weight and data-retention models stay disabled by default. Admins can override any individual model to make durable, intentional decisions.

→ Changelog: Global model policy generally available

3. Copilot code review adds depth and coverage controls

Effort levels (Lite and Balanced) are now generally available with org-level defaults, letting you match review depth to risk. Reviews now cover bot-authored and cloud-agent pull requests, drop the 300-file limit, and let reviewers record why a comment was resolved — richer signal and governance for admins.

Sources:
→ Changelog: Copilot code review effort levels are generally available
→ Changelog: Copilot code review: Resolution reasons and expanded capabilities

4. Impact dashboard adds a return on investment section

A new "Potential return on investment" section connects Copilot spend to pull request output, comparing passive users against agent-first developers. A salary selector recalculates cost-derived metrics instantly, so admins can model ROI against payroll assumptions and target enablement at the phases with the most headroom.

→ Changelog: Copilot impact dashboard adds a return on investment section

5. Deeper usage and cost transparency

The usage metrics API now breaks out third-party agent app activity per agent across enterprise and org reports, so you can compare adoption and ground licensing decisions in real data. Separately, the AI usage report now shows per-model input, output, and cached token breakdowns behind each AI credit.

Sources:
→ Changelog: Copilot usage metrics API adds agent app activity
→ Changelog: Per-model token breakdown in the usage report

6. Managed settings governance arrives in JetBrains

Enterprise managed settings now extend to Copilot for JetBrains: control plugins and marketplaces, apply MCP allowlists to block servers outside your enterprise list, and centrally configure OpenTelemetry so Copilot telemetry is routed consistently to your approved collector. Managed values take precedence over developer settings.

→ Changelog: Enterprise managed settings in GitHub Copilot for JetBrains

7. Trigger Copilot automations from comments

You can now create Copilot cloud agent automations that run when an issue or pull request comment matches text you specify. It is a lightweight way to standardize agent workflows — note that Business and Enterprise users need the Copilot cloud agent policy enabled by an administrator first.

→ Changelog: Trigger Copilot automations with comments
