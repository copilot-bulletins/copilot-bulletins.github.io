Biweekly #7 · June 1 to June 14, 2026 · Devs Edition

🎯 This edition's thread

This period, agentic development moved from experiment toward everyday infrastructure. Copilot's agent capabilities matured in parallel across the terminal, the IDE, and a new desktop app, while larger context windows and configurable reasoning gave those agents more room to work. For developers, the practical takeaway: running, steering, and trusting agents across surfaces is becoming part of the daily workflow.

🏆 Top 5 updates

1. Visual Studio Code goes agent-first

VS Code's May releases (v1.120–v1.123) bring the Agents window to Stable (preview) for agent-first, multi-project work, plus remote agents over SSH and Dev Tunnels that keep running after you disconnect. BYOK now reaches air-gapped environments and utility-task model selection.

→ Changelog: GitHub Copilot in Visual Studio Code, May releases

2. One-million-token context and configurable reasoning

Copilot now supports one-million-token context windows for working across large codebases and multi-file projects without losing context. Configurable reasoning levels balance speed and depth for your hardest architectural and debugging work, available now in VS Code, Copilot CLI, and the Copilot app.

→ Changelog: Larger context windows and configurable reasoning levels for GitHub Copilot

3. Copilot CLI levels up

Copilot CLI had a big two weeks. Rubber duck (a built-in critic agent) and voice input went GA, an experimental redesigned terminal adds tabs for issues, PRs, and gists, and the new /settings command unifies all configuration into one discoverable, schema-validated surface.

Sources:
→ Changelog: Copilot CLI: Improved UI, rubber duck, prompt scheduling, and voice input
→ Changelog: Copilot CLI: Configure everything from one place with /settings

4. The GitHub Copilot app opens up

The GitHub Copilot app, the desktop home for agent-native development, opened its technical preview to all paid Copilot tiers. Run parallel agent sessions on isolated worktrees from one My work view, and use canvases to make agent output visible and verifiable.

Sources:
→ Blog: GitHub Copilot app: The agent-native desktop experience
→ Changelog: Expanded technical preview availability for the GitHub Copilot app

5. Cloud and local sandboxes for safe agents

Copilot can now run inside secure, isolated sandboxes — locally on your machine or in GitHub-hosted cloud environments. As agents execute commands and modify files on your behalf, sandboxes give them a safe place to work within the policies you define.

→ Changelog: Cloud and local sandboxes for GitHub Copilot now in public preview
