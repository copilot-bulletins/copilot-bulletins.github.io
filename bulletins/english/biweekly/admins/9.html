🏆 Top 5 updates

1. Enterprise managed-settings.json is generally available

Administrators can now enforce Copilot configuration across their estate using a centrally managed settings file, now GA. This delivers consistent, auditable policy for editors and agents without relying on individual user setup.

→ Changelog: Enterprise managed-settings.json is generally available

2. Deploy managed Copilot settings via MDM in VS Code and CLI

Managed settings can now be pushed through your MDM solution to VS Code and the Copilot CLI. This lets IT teams provision and lock down Copilot configuration at scale using existing device-management tooling.

→ Changelog: Deploy managed Copilot settings via MDM in VS Code and CLI

3. Review cycles and time-to-adoption phases in the usage API

The usage API now exposes review cycles and time-to-adoption phases, giving administrators deeper, programmatic insight into how teams progress from onboarding to active use—ideal for building custom adoption dashboards and reporting.

→ Changelog: Add review cycles and time to adoption phases in the usage API

4. Per-user budgets for cost centers in the billing UI

Cost center owners can now set per-user budgets directly in the billing UI, enabling finer-grained spend governance. This helps administrators cap and predict usage-based costs at the individual level across departments.

→ Changelog: Per-user budgets for cost centers in the billing UI

5. Agentic autofix for code scanning alerts in public preview

Copilot can now automatically propose fixes for code scanning alerts, now in public preview. For security-conscious administrators, this accelerates remediation while keeping fixes reviewable within existing code scanning workflows.

→ Changelog: Agentic autofix for code scanning alerts in public preview
