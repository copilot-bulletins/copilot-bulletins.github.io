Biweekly #13 · September 1 to September 14, 2026 · Admins Edition

🎯 This edition's thread

Administrative control was the dominant theme this period. GitHub shipped enterprise-managed permissions for agent operations, extended content-exclusion enforcement to the Copilot app and CLI, and added budget expiration dates. For admins, the takeaway is clear: as Copilot's agentic surface expands, so does the governance tooling to keep operations, spend, and sensitive code within policy.

⚠️ Heads up

  • Upcoming deprecation of selected GitHub Copilot models — Deadline: October 2, 2026 — Several models (including Claude Opus 4.7 and Gemini 3.5/3.6 Flash) will be removed across all Copilot experiences. Verify alternative models are enabled in your Copilot model policies before the date.

🚀 Take action

  • Review which agent operations should be blocked, gated, or auto-approved using enterprise-managed policies.
  • Confirm your content exclusion rules cover repositories now that the Copilot app and CLI enforce them.
  • Set expiration dates on temporary budgets via budget controls.
  • Track VS Code Agents adoption in your usage metrics.
  • Questions or need support? Reach out to your GitHub team, we're here to help.

🏆 Top 5 updates

1. Centralized control over agent operations

Copilot Business and Enterprise admins can now centrally decide which agent operations are blocked, require human approval, or run without a prompt. This gives governance teams a single lever to constrain the growing agentic surface across the organization.

→ Changelog: Enterprise-managed permissions for GitHub Copilot agent operations

2. Content exclusions now enforced in the Copilot app and CLI

The Copilot app and Copilot CLI now respect content exclusion policies set by enterprise, organization, and repository admins. Sensitive files you already protect in the IDE stay protected across these newer surfaces, closing a governance gap without extra configuration.

→ Changelog: Content exclusions generally available in Copilot app and CLI

3. VS Code Agents activity in usage metrics

Usage metrics reports now include GA metrics for the dedicated VS Code Agents window, with daily active users and per-user session and message counts across 1-day and 28-day periods. Admins gain visibility into agent adoption and engagement for reporting and rollout decisions.

→ Changelog: Add VS Code agents to Copilot usage metrics

4. Expiration dates for individual user budgets

You can now set an optional expiration date on an individual user budget, and GitHub removes it automatically on that date. The user then falls back to their cost center or universal budget—useful for time-boxed trials or temporary allocations without manual cleanup.

→ Changelog: Set an expiration date for individual user budgets

5. Copilot code review can now approve pull requests

Copilot now signals when a PR is ready to approve, and admins can authorize it to sign off. The capability is off by default and configurable at the enterprise, organization, and repository level, giving review governance teams granular control.

→ Changelog: Copilot code review can now approve pull requests
