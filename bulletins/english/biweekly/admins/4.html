🏆 Top 5 updates

1. GitHub Copilot transitions to usage-based billing with AI Credits on June 1

Premium request units (PRUs) are being replaced by GitHub AI Credits, a token-based model pooled across your organization. Existing Copilot Business customers receive 3,000 AI Credits per user per month for June–August; Enterprise customers receive 7,000. New budget controls let admins enforce or alert at the enterprise, organization, cost-center, and user levels.

→ Blog: GitHub Copilot is moving to usage-based billing

2. Copilot code review adds GitHub Actions minutes billing on June 1

Copilot's agentic code review runs on GitHub Actions infrastructure. Starting June 1, each review on private repositories will consume Actions minutes from your plan entitlement—in addition to AI Credits. Public repositories remain free. Admins should audit Actions budgets and runner settings; self-hosted runners are not subject to Actions minute charges.

→ Changelog: GitHub Copilot code review will start consuming GitHub Actions minutes on June 1, 2026

3. GPT-5.5 is generally available for Copilot Business and Enterprise

OpenAI's latest model is rolling out across all Copilot surfaces—VS Code, JetBrains, github.com, Visual Studio, Copilot CLI, and GitHub Mobile. Business and Enterprise admins must enable the GPT-5.5 policy before users can select it. It launches with a 7.5× promotional multiplier; factor this into AI Credit consumption estimates.

→ Changelog: GPT-5.5 is generally available for GitHub Copilot

4. Claude Opus 4.7 arrives as Opus 4.5 and 4.6 phase out of Pro+

Anthropic's latest Opus model is now available for Copilot Business and Enterprise—admins must enable the policy. Opus 4.7 delivers stronger multi-step agentic task performance. Simultaneously, Opus 4.5 and 4.6 are being removed from the Pro+ model picker; advise users on those plans to switch to Opus 4.7.

→ Changelog: Claude Opus 4.7 is generally available

5. Breaking change: GitHub App installation token format is changing

Starting April 27, GitHub App installation tokens shift from 40 characters to ~520 characters in a staged rollout through late June. This affects GITHUB_TOKEN in Actions workflows and server-to-server tokens used by integrations. Any code or database column validating token length must be updated to treat tokens as opaque strings before broad enablement.

→ Changelog: Notice about upcoming new format for GitHub App installation tokens
