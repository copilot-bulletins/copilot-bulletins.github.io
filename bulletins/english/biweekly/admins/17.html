Biweekly #17 · November 1 to November 14, 2026 · Admins Edition

🎯 This edition's thread

This period centered on visibility and programmatic control. Usage metrics now show whether AI feedback is acted on, where telemetry is missing and how self-managed models are used, while more settings move to APIs and GitHub Apps. For admins, this means fewer reporting gaps and governance that can be automated rather than managed by hand.

🏆 Top 5 updates

1. Code review settings, now managed by API

Enterprise, organization and repository admins can now read and update Copilot code review settings through REST and GraphQL, including enablement, default review effort and runners. Enterprise-managed settings can't be overridden. Attribution fields also identify Copilot's reviews and the sources it used.

→ Changelog: Copilot code review: API management and review overview updates

2. Measure whether code review feedback lands

Repository-level usage metrics now include a copilot_code_review object. It reports comments evaluated and addressed, broken down by severity, review tier, comment type and customization, plus merged pull requests with no later human change request. You can use it to track an addressed rate for each repository.

→ Changelog: Usage metrics API adds code review details and addressed rate

3. Close blind spots in usage reporting

New per-user fields flag missing client telemetry and IDE or extension versions below the usage metrics minimums. BYOK usage, both local keys and enterprise custom models, is now reported separately from usage of Copilot-hosted models.

Sources:
→ Changelog: Usage metrics API flags telemetry and version gaps
→ Changelog: BYOK and enterprise custom models in the Copilot usage API

4. Claude Fable 5.2 requires an explicit opt-in

Claude Fable 5.2 is generally available, but its policy is off by default. The model requires data retention for Anthropic's safety classifiers, and enabling the policy acknowledges this. Eligible enterprises can request zero data retention access through their account team.

→ Changelog: Claude Fable 5.2 in GitHub Copilot

5. GitHub Apps can now manage Copilot seats

Enterprise GitHub Apps can now call the enterprise-level Copilot seat management APIs to assign seats to users and enterprise teams. Access uses the new "Enterprise Copilot license management" fine-grained permission, so seat automation no longer has to depend on personal tokens.

→ Changelog: GitHub App support for Enterprise Copilot seat management
