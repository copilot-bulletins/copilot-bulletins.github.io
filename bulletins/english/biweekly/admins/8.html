Biweekly #8 · June 15 to June 30, 2026 · Admins Edition

🎯 This edition's thread

As agentic and credit-based consumption scales, GitHub turned its attention this period to the administrator's control plane. The updates cluster around three levers: governing spend, seeing consumption clearly, and enforcing configuration standards across clients. For administrators, the message is operational maturity—the tooling to fund teams predictably, measure real adoption, and keep agent behavior within policy is now arriving together rather than piecemeal.

⚠️ Heads up

  • Opus 4.6 (fast) has been deprecated — Deadline: June 29, 2026 — The model was retired across all Copilot experiences on this date. Enterprise admins should confirm the suggested successor, Opus 4.8 (fast), is enabled in their model policies so users keep uninterrupted access.

🚀 Take action

  • Cap spend before it starts: set a per-user AI credit budget on your cost centers so limits follow team membership automatically.
  • See consumption next to adoption: track per-user credit use and fuller active-user coverage in your Copilot usage metrics.
  • Lock down clients: restrict plugin sources with strictKnownMarketplaces and turn off auto-approve with disableBypassPermissionsMode in enterprise-managed settings.
  • Standardize reviews: set an organization-level default level for Copilot code review.
  • Questions or need support? Reach out to your GitHub team, we're here to help.

🏆 Top 5 updates

1. Fund teams without managing thousands of budgets

Enterprise admins can set one per-user AI credit budget on a cost center; it follows membership automatically as people join or move teams. Because it counts included usage, it can stop a user before metered charges begin—replacing the need for thousands of individual budgets.

→ Changelog: Per-user AI credit budgets available for cost centers

2. Credit consumption now sits inside your usage metrics

The usage metrics API now reports per-user AI credits used, so you can see consumption next to the work that drove it and plan for usage-based billing. Reports also draw on server-side telemetry, surfacing active, billed users that client signals alone would have missed.

Sources:
→ Changelog: AI credits consumed per user now in the Copilot usage metrics API
→ Changelog: Copilot usage metrics now include more of your active users

3. Enterprise-managed settings add real governance controls

Two new enterprise-managed settings tighten client governance. strictKnownMarketplaces limits plugin installs in VS Code and Copilot CLI to marketplaces you approve, while disableBypassPermissionsMode blocks auto-approve ("yolo mode"). Both apply automatically to Copilot Business and Enterprise users before tools run.

Sources:
→ Changelog: Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI
→ Changelog: Enterprise-managed settings now support bypass permission controls

4. Copilot code review gains org defaults and repo context

Organizations can now set a default review level for unconfigured repositories, with repos still able to override it, and Medium-depth runs are labeled in pull request overviews. Copilot code review also reads a repository's root AGENTS.md to align feedback with your conventions.

Sources:
→ Changelog: Copilot code review: Analysis depth and efficiency updates
→ Changelog: Copilot code review: AGENTS.md support and UI improvements

5. Measure merged pull requests by AI adoption phase

Enterprise and organization reports now include a total of pull requests merged for each AI adoption phase, not just per-user averages. That lets you calculate each phase's share of merged PRs and measure how delivery throughput shifts as teams progress through adoption.

→ Changelog: Track total merges by adoption phase in enterprise and organization reports
