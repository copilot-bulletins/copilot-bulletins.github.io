Biweekly #16 · October 15 to October 31, 2026 · Admins Edition

🎯 This edition's thread

Late October moved Copilot administration away from managing seats and toward managing policy and budgets. Licensing, plugins, agent permissions and model access now come with central controls and APIs. Usage reporting now also covers tools outside the IDE. For admins, this means fewer manual steps and more of the governance work handled through policy.

  • GitHub Copilot models deprecated on October 19, 2026 — Action required — GPT-5.5, GPT-5.4, GPT-5 mini, Gemini 3.7 Flash and Grok 4.5 have been retired. Update any workflows and integrations that still use them.

🏆 Top 5 updates

1. Copilot is now included with GitHub Enterprise

Enterprises working with a GitHub or Microsoft account team can now get Copilot included for every GitHub Enterprise licensed user. AI usage is metered against your enterprise budget from the first request. Code completion keeps working even when the budget runs out.

→ Changelog: GitHub Enterprise now includes access to GitHub Copilot

2. Enterprise plugin controls are generally available

Through managed settings, admins can now require plugins, block plugins and restrict installation to approved marketplaces in VS Code, Copilot CLI and the Copilot app. Required plugins are installed automatically and users can't disable them. Managed settings take precedence over repository and personal choices.

→ Changelog: Repository plugin defaults and enterprise plugin controls generally available

3. Assisted permissions with enterprise guardrails

A model now evaluates each command, file-path or URL request. Requests it classifies as clearly safe run automatically, and all others need approval. Enterprise admins can block "Allow All" while keeping Assisted available, disable Assisted, or set the default permission mode for new sessions.

→ Changelog: GitHub Copilot assisted permissions generally available

4. Broader visibility in the usage metrics API

The usage metrics API now reports usage by client, including tools such as OpenCode, Claude Code and Codex. Skills, custom agents and MCP servers built by your teams now appear by name, with up to 25 entries per record. This lets you track adoption of internal tooling.

Sources:
→ Changelog: Usage metrics API adds usage from tools like OpenCode
→ Changelog: Custom skills, agents, and MCP servers in usage metrics API

5. Manage model policies through the REST API

GET and PATCH endpoints are now generally available for Copilot model policies at the enterprise, enterprise team, agent app and organization levels. You can manage model availability as code and delegate control to organizations or teams.

→ Changelog: Copilot model policy API for enterprise, orgs, and teams
