Biweekly #14 · September 15 to September 30, 2026 · Admins Edition

🎯 This edition's thread

This period centered on administrative control and visibility. GitHub shipped a new default-enablement policy, in-product settings validation, deeper usage and adoption metrics, and open observability for agents. For admins, the message is clear: governing Copilot at scale now comes with stronger guardrails, clearer data, and fewer configuration surprises.

🏆 Top 5 updates

1. A new default policy for Copilot features

A new global default policy governs generally available features and client capabilities in enterprise and organization settings. For 28 days you can configure it without affecting users, giving admins time to decide how new capabilities roll out before enforcement begins.

→ Changelog: Default Enablement of Copilot features for Copilot Business and Enterprise

2. Feature engagement in the impact dashboard

The Copilot impact dashboard now shows how many active users regularly use key features, with a 28-day engagement breakdown. Admins can quickly see which experiences are widely adopted and which need more enablement, and the same data is available via enterprise and organization report APIs.

→ Changelog: Copilot impact dashboard now shows feature engagement

3. Budget increase requests are generally available

When a member exhausts their AI credits, they can now request more budget the moment they hit the limit. Admins approve, adjust, or deny requests without leaving settings, and requests route automatically to whichever account pays for the budget.

→ Changelog: Copilot budget increase requests are generally available

4. OpenTelemetry for agent observability

The GitHub Copilot app now supports OpenTelemetry through enterprise-managed settings. Admins can stream agent activity data to compatible monitoring tools to analyze sessions, trace model and tool requests, and investigate unexpected behavior, bringing agent operations into existing observability pipelines.

→ Changelog: OpenTelemetry in the GitHub Copilot app

5. In-product validator for managed settings

A new in-product validator catches malformed JSON, unsupported configurations, and invalid team mappings before they silently block policy enforcement. Each issue identifies the affected file and JSON path in the enterprise AI controls page, making misconfigured policies far easier to diagnose.

→ Changelog: Enterprise managed settings in-product validator
