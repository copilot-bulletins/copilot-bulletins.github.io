Monthly #7 · September 2026 · Admins Edition

🎯 This edition's thread

September centered on one theme for administrators: governing an increasingly agentic Copilot at scale. As agents gained autonomy across IDEs, CLI, and pull requests, GitHub shipped matching controls — enterprise-managed permissions, content exclusions, budget guardrails, and richer usage metrics. The operational message is clear: capability and governance are advancing in lockstep, so policies and defaults deserve a fresh review now.

⚠️ Heads up

  • Upcoming deprecation of selected GitHub Copilot models in mid-October — Deadline: mid-October 2026 — Review which models your teams rely on and align defaults via enterprise policies before retirement.
  • Default Enablement of Copilot features for Copilot Business and Enterprise — Action required — Newly released features will be on by default; confirm your managed settings reflect your intended posture.

🚀 Take action

  • Standardize agent and model governance with enterprise managed settings.
  • Protect sensitive code by configuring content exclusions across repositories.
  • Measure value and adoption in the Copilot impact dashboard.
  • Control spend with budget increase requests and limits.
  • Questions or need support? Reach out to your GitHub team, we're here to help.

🏆 Top 5 updates of the month

1. Enterprise-managed governance tightens around agents and models

Admins gained centralized, non-overridable control this month: managed permissions for agent operations, a settings in-product validator, and support for any default model. Together they let enterprises enforce consistent guardrails as Copilot's agentic surface widens.

Sources:
→ Changelog: Enterprise managed permissions for GitHub Copilot agent operations
→ Changelog: Enterprise-managed settings support any default model
→ Changelog: Enterprise managed settings in-product validator

2. Copilot code review matures into a governed workflow

Copilot code review can now approve pull requests, resolve and analyze comments automatically, and be requested and configured in more ways. For admins, this makes AI review a policy-manageable stage in the delivery lifecycle rather than an ad-hoc assist.

Sources:
→ Changelog: Copilot code review can now approve pull requests
→ Changelog: Auto-resolution and analysis updates in Copilot code review
→ Changelog: More ways to request and configure Copilot code reviews

3. Usage and adoption metrics get deeper and more exportable

Visibility expanded across the board: the impact dashboard now shows feature engagement, VS Code agents and agentic CLI customizations flow into usage metrics, the API adds PR review stages, and OpenTelemetry enables standardized observability. Admins can prove ROI and spot gaps precisely.

Sources:
→ Changelog: Copilot impact dashboard now shows feature engagement
→ Changelog: Usage metrics API adds pull request review stages
→ Changelog: OpenTelemetry in the GitHub Copilot app

4. Budget controls become more precise

Spending governance advanced with expiration dates for individual user budgets and generally available budget increase requests. Admins can now cap exposure per user, time-box allocations, and handle overage requests through a managed workflow instead of manual exceptions.

Sources:
→ Changelog: Set an expiration date for individual user budgets
→ Changelog: Copilot budget increase requests are generally available

5. Content exclusions reach general availability in the Copilot app and CLI

Content exclusion enforcement now extends to the Copilot app and CLI, closing a gap as Copilot moves beyond the IDE. Admins get consistent protection of sensitive files across more surfaces, strengthening compliance and reducing accidental exposure.

→ Changelog: Content exclusions generally available in Copilot app and CLI
