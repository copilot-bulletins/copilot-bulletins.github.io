Monthly #6 · August 2026 · Admins Edition

🎯 This edition's thread

August centered on enterprise governance and measurement. GitHub gave administrators finer control over managed settings, model policy, and MCP access, while sharpening the tools to prove Copilot's value. For admins, the throughline is clear: scale adoption confidently by tightening guardrails and grounding every rollout decision in usage, cost, and ROI data.

⚠️ Heads up

  • Upcoming changes to GitHub Copilot policies and billing — Action required — Cloud agent and Chat experiences are converging to a single policy, and the Copilot code review default is changing to Balanced effort. Review your enterprise policies before the change takes effect.
  • Upcoming deprecation of MAI-Code-1-Flash — Deadline: September 10, 2026 — Migrate workflows to MAI-Code-1.1-Flash and confirm it is enabled in your model availability settings.
  • Retiring the Copilot Billing Preview app — Action required — The app is no longer available; manage spend, budgets, and cost centers directly in your billing settings.

  • Standardize governance across IDEs with enterprise managed settings.
  • Control which models your users can access via model availability and policy.

🏆 Top 5 updates of the month

1. Enterprise managed settings scale across your fleet

Governance got more granular this month. Admins can now target enterprise teams with itemized configuration, enforce MCP server allowlists, apply managed settings in JetBrains, and auto-update approved plugin marketplaces — scaling guardrails without bottlenecking every change centrally.

Sources:
→ Changelog: Enterprise team specialization for managed settings
→ Changelog: MCP allowlists in enterprise managed settings
→ Changelog: Enterprise managed settings in GitHub Copilot for JetBrains
→ Changelog: Enterprise-managed settings now support autoUpdate for plugin marketplaces

2. Global model policy is generally available

The default model policy is now enforced enterprise-wide. Previously unconfigured and newly released models inherit your global setting via a live "Delegate to default policy" state, while open-weight and data-retention models stay disabled by default — giving admins durable, predictable model governance.

→ Changelog: Global model policy generally available

3. Prove impact with ROI, agent, and token-level metrics

Measurement matured on three fronts: the impact dashboard added a Potential ROI section tying spend to pull request output, the usage metrics API now reports agent app activity, and the usage report shows a per-model token breakdown — making it easier to justify and optimize Copilot spend.

Sources:
→ Changelog: Copilot impact dashboard adds a return on investment section
→ Changelog: Copilot usage metrics API adds agent app activity
→ Changelog: Per-model token breakdown in the usage report

4. Copilot code review adds effort levels and resolution reasons

Code review governance improved. Effort levels (Lite and Balanced) are now generally available with organization-level defaults, and reviews now surface comment resolution reasons alongside expanded capabilities — helping admins tune review depth and audit how feedback is handled.

Sources:
→ Changelog: Copilot code review effort levels are generally available
→ Changelog: Copilot code review: Resolution reasons and expanded capabilities

5. The model catalog keeps expanding

Four models arrived this month: Gemini 3.7 Flash, Grok 4.6, Kimi K3, and MAI-Code-1.1-Flash. With global model policy now GA, admins can decide which of these reach their users and keep their available model set aligned with organizational risk and cost requirements.
