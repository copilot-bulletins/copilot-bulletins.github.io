Monthly #4 · June 2026 · Admins Edition

🎯 This edition's thread

June centered on control and visibility for administrators. GitHub expanded enterprise-managed client settings, added per-user credit budgets to cost centers, and enriched usage metrics with adoption and consumption data. In parallel, code review and agent security gained governance controls. The through-line: managing Copilot at scale is becoming a first-class, policy-driven administrative discipline rather than an afterthought.

⚠️ Heads up

  • GPT-4.1 deprecated — Action required — GPT-4.1 was retired across Copilot experiences on June 1. Confirm your enterprise model policies enable a supported alternative so users keep access.
  • GPT-5.2 and GPT-5.2-Codex deprecated — Action required — Both were retired across most experiences on June 5 (GPT-5.2 remains available in Copilot code review). Point workflows to a supported model.
  • Upcoming deprecation of Opus 4.6 (fast) — Action required — Opus 4.6 (fast) was retired on June 29. Verify your model policies route users to a current alternative.

🚀 Take action

  • Cap Copilot spend by attaching per-user AI credit budgets to cost centers, so budgets follow team membership automatically.
  • Tighten client governance: define enterprise plugin standards and disable automatic command approval in enterprise-managed settings.
  • Measure adoption and cost with the enriched Copilot usage metrics, now including per-user AI credits and merges by adoption phase.
  • Review your enterprise model policies so users are routed to supported models after June's deprecations.
  • Questions or need support? Reach out to your GitHub team, we're here to help.

🏆 Top 5 updates of the month

1. Cap Copilot spend with per-user credit budgets

Admins can now attach one per-user AI credit budget to a cost center; it follows membership as people join or move teams. Fund a platform team at $250 and everyone else at $40 without creating thousands of individual budgets to control spend.

Sources:
→ Changelog: Per-user AI credit budgets available for cost centers
→ Changelog: Updates to GitHub Copilot billing and plans

2. Enterprise-managed settings gain real governance controls

Managed client settings gained real teeth. Admins can enforce strictKnownMarketplaces to restrict plugin sources, disable bypass ("yolo") permission mode, and push managed plugins to VS Code alongside Copilot CLI. Settings apply automatically to every Business and Enterprise user, enforcing governance before tools run.

Sources:
→ Changelog: Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI
→ Changelog: Enterprise-managed settings now support bypass permission controls
→ Changelog: Enterprise-managed plugins in VS Code in public preview

3. Copilot code review becomes more configurable and efficient

Code review added organization-level controls: default review-effort levels, self-hosted runner selection, content-exclusion support, AGENTS.md context, and skills/MCP integration. A new Medium analysis tier matches depth to change complexity, while CLI-based file tools cut review cost, helping admins standardize quality across repositories.

Sources:
→ Changelog: Copilot code review: New configurations and controls
→ Changelog: Copilot code review: Analysis depth and efficiency updates
→ Changelog: Shape Copilot code review around your team

4. Deeper visibility into Copilot usage and adoption

The usage metrics API now reports AI credits consumed per user and total merges by adoption phase, while reports draw on server-side telemetry to surface active users that client signals alone missed. Admins get a more complete, consistent picture of adoption and cost.

Sources:
→ Changelog: Copilot usage metrics now include more of your active users
→ Changelog: AI credits consumed per user now in the Copilot usage metrics API
→ Changelog: Track total merges by adoption phase in enterprise and organization reports

5. Automatic security validation for third-party agents

Code from third-party coding agents (including Claude and OpenAI Codex) now gets the same automatic security validation as Copilot cloud agent: CodeQL analysis, Advisory Database dependency checks, and secret scanning, with fixes applied before the PR is finalized. A new CLI /security-review command adds on-demand scans.

Sources:
→ Changelog: Security validation for third-party coding agents
→ Changelog: Dedicated security review command now available in Copilot CLI
