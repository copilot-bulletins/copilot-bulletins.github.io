Monthly (Long) #1 · Mai 2026 · Admins Edition

🎯 Le fil de cette édition

Le mois de mai marque un tournant décisif pour les administrateurs Copilot : deux grandes dynamiques se conjuguent. D'une part, les outils de gouvernance s'affinent — règles de modèles par organisation, secrets centralisés pour les agents, plugins gérés en entreprise — permettant un contrôle granulaire à chaque couche de l'outillage. D'autre part, la maturité opérationnelle progresse : les métriques d'utilisation s'enrichissent (cohortes d'adoption, ventilation par équipe) et la facturation à la consommation entre en vigueur dès le 1er juin. C'est un mois de fond, pensé pour les administrateurs qui pilotent le déploiement Copilot à l'échelle.

⚠️ Attention

  • Dépréciation de GPT-4.1 — Délai : 1er juin 2026 — Mettez à jour vos workflows et intégrations vers GPT-5.5 ; les administrateurs Enterprise doivent activer l'accès au modèle alternatif via les politiques de modèles Copilot.
  • Dépréciation de GPT-5.2 et GPT-5.2-Codex — Délai : 5 juin 2026 — Migrez vers GPT-5.5 ou GPT-5.3-Codex avant cette date ; vérifiez les politiques de modèles dans vos paramètres Copilot Enterprise.

🚀 Passez à l'action

  • Vérifiez et mettez à jour vos politiques de modèles Copilot avant le 5 juin pour éviter toute interruption de service.
  • Configurez des règles de modèles ciblées par organisation pour un contrôle granulaire des accès aux modèles IA selon vos entités.
  • Téléchargez les rapports d'avril pour estimer la consommation en crédits IA de votre organisation avant le démarrage de la facturation.
  • Analysez l'adoption Copilot via les métriques par équipe pour cibler vos actions d'activation là où elles auront le plus d'impact.
  • Questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 8 des mises à jour du mois

1. Métriques d'adoption IA : cohortes et ventilation par équipe dans l'API d'utilisation

L'API Copilot usage metrics classe désormais chaque utilisateur selon sa phase d'adoption IA (code, agent, multi-agent) sur une fenêtre glissante de 28 jours. En parallèle, un nouveau rapport user-teams permet de ventiler les métriques par équipe. Ensemble, ces ajouts transforment le suivi de l'adoption en outil de pilotage ciblé.

Sources:
→ Changelog: Copilot usage metrics API adds cohorts for AI adoption
→ Changelog: Team-level Copilot usage metrics now available via API

2. Règles de modèles ciblées par organisation

Les propriétaires d'entreprise peuvent désormais définir des règles d'accès aux modèles Copilot spécifiques à certaines organisations, au-delà de la configuration globale de l'entreprise. Cette fonctionnalité en préversion publique offre le contrôle granulaire attendu pour les déploiements multi-entités sur Copilot Business et Enterprise.

→ Changelog: Target Copilot models to organizations with model rules

3. GPT-5.3-Codex : nouveau modèle de base LTS pour Copilot Business et Enterprise

GPT-5.3-Codex est désormais le modèle de base pour tous les plans Business et Enterprise, remplaçant GPT-4.1. Premier modèle LTS en partenariat avec OpenAI, il est garanti disponible jusqu'au 4 février 2027 — une stabilité appréciable pour les cycles de validation sécurité internes des entreprises.

→ Changelog: GPT-5.3-Codex is now the base model for Copilot Business and Enterprise

4. Facturation à la consommation : les rapports d'avril disponibles pour planifier

À partir du 1er juin, GitHub Copilot bascule vers une facturation en crédits IA. Les rapports d'avril sont disponibles pour estimer la consommation par modèle et par surface d'usage. Chaque plan Business inclut 1 900 crédits/utilisateur/mois (3 000 pendant les 3 premiers mois pour les clients existants).

→ Changelog: April reports are now available to prepare for usage-based billing

5. Secrets et variables dédiés pour Copilot cloud agent au niveau organisation

Les secrets et variables du Copilot cloud agent ont désormais leur propre section "Agents" dans les paramètres, configurable au niveau organisation. Plus besoin de dupliquer la configuration sur chaque dépôt : un gain significatif pour les déploiements à grande échelle et la gestion de serveurs MCP partagés.

→ Changelog: More flexible secrets and variables for Copilot cloud agent

6. Plugins gérés par l'entreprise pour Copilot CLI

Les administrateurs peuvent désormais définir des plugins standardisés pour Copilot CLI à l'échelle de l'entreprise, via un fichier settings.json dans le dépôt .github-private. Agents, hooks et configurations MCP sont déployés automatiquement à l'authentification — une avancée majeure pour la gouvernance des outils CLI à l'échelle.

→ Changelog: Enterprise-managed plugins in GitHub Copilot CLI are now in public preview

7. API Copilot Spaces en disponibilité générale

L'API Copilot Spaces est désormais stable et permet de créer, lire, mettre à jour et supprimer des Spaces par programmation — ainsi que gérer leurs collaborateurs et ressources. Pour les entreprises gérant de nombreux Spaces de contexte, c'est l'ouverture à une automatisation et une gestion centralisée sans manipulation manuelle.

→ Changelog: Copilot Spaces API now generally available

8. Déclencher des tâches Copilot cloud agent via l'API REST

Il est maintenant possible de démarrer des tâches Copilot cloud agent directement via l'API REST, ouvrant la voie à l'intégration dans des pipelines CI/CD ou des systèmes d'orchestration internes. Les administrateurs peuvent ainsi automatiser le déclenchement de travaux d'agent sans passer par l'interface GitHub.

→ Changelog: Start Copilot cloud agent tasks via the REST API
