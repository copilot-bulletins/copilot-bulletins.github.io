Monthly (Long) #3 · Juin 2026 · Admins Edition

🎯 Le fil de cette édition

En juin, la gouvernance et la maîtrise des coûts s'imposent pour les administrateurs. À mesure que les capacités agentiques se généralisent, GitHub livre les contrôles pour les encadrer : budgets de crédits IA par utilisateur adossés aux cost centers, paramètres gérés par l'entreprise verrouillant marketplaces et permissions, télémétrie d'adoption plus complète et validation de sécurité étendue aux agents tiers. Objectif : piloter la consommation, appliquer vos politiques avant l'exécution des outils et mesurer l'adoption sur des données fiables — déployer Copilot à l'échelle sans sacrifier visibilité ni conformité.

⚠️ Attention

  • GPT-4.1 deprecated — Effectif depuis le 1er juin 2026 — Retiré de toutes les expériences Copilot. Confirmez qu'un modèle pris en charge est activé dans vos politiques.
  • GPT-5.2 and GPT-5.2-Codex deprecated — Effectif depuis le 5 juin 2026 — Retirés de la plupart des surfaces (GPT-5.2 reste disponible pour la revue de code). Basculez vos utilisateurs vers un modèle alternatif.
  • Upcoming deprecation of Opus 4.6 (fast) — Effectif depuis le 29 juin 2026 — Opus 4.6 (fast) est retiré ; migrez workflows et intégrations vers un modèle équivalent.

🚀 Passez à l'action

  • Plafonnez la consommation en créant des budgets de crédits IA par utilisateur sur vos cost centers.
  • Renforcez votre gouvernance via les paramètres gérés par l'entreprise : marketplaces autorisées et blocage de l'auto-approbation.
  • Mesurez adoption et coûts avec les métriques d'usage Copilot, enrichies des crédits par utilisateur et des fusions par phase.
  • Des questions ou besoin d'aide ? Contactez votre équipe GitHub, nous sommes là pour vous accompagner.

🏆 Top 7 des mises à jour du mois

1. Gouvernance des coûts IA : budgets par utilisateur sur les cost centers

Les administrateurs peuvent fixer un budget de crédits IA par utilisateur au niveau d'un cost center : il s'applique à chaque membre et suit les mouvements d'équipe, sans reconfiguration. L'API de métriques expose désormais les crédits consommés par utilisateur.

Sources:
→ Changelog: Per-user AI credit budgets available for cost centers
→ Changelog: AI credits consumed per user now in the Copilot usage metrics API

2. Revue de code Copilot : analyse plus fine, coûts réduits et contrôles d'équipe

Le niveau « Medium » devient configurable par défaut au niveau org, les coûts baissent d'environ 20 %, les exclusions de contenu sont respectées et les skills/MCP alignent les revues sur vos standards.

Sources:
→ Changelog: Copilot code review: Analysis depth and efficiency updates
→ Changelog: Copilot code review: New configurations and controls
→ Changelog: Shape Copilot code review around your team

3. Paramètres gérés par l'entreprise : marketplaces, permissions et plugins verrouillés

Trois leviers : strictKnownMarketplaces restreint les plugins aux marketplaces approuvées, disableBypassPermissionsMode bloque l'auto-approbation des commandes (« yolo mode ») et les plugins gérés par l'entreprise s'étendent à VS Code (v1.122+), au-delà du CLI.

Sources:
→ Changelog: Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI
→ Changelog: Enterprise-managed settings now support bypass permission controls
→ Changelog: Enterprise-managed plugins in VS Code in public preview

4. Mesure de l'adoption : fusions par phase et couverture élargie des utilisateurs actifs

Les rapports d'entreprise et d'organisation exposent désormais le nombre total de pull requests fusionnées par phase d'adoption de l'IA, et la télémétrie côté serveur fait remonter des utilisateurs actifs auparavant invisibles, pour une couverture plus fidèle.

Sources:
→ Changelog: Track total merges by adoption phase in enterprise and organization reports
→ Changelog: Copilot usage metrics now include more of your active users

5. Sécurité des agents : validation automatique des agents tiers et revue de sécurité

La validation de sécurité automatique (CodeQL, base d'avis, secret scanning) couvre désormais le code des agents tiers comme Claude et Codex. La commande /security-review du CLI détecte 11 catégories de vulnérabilités ; les agentic workflows se passent de PAT.

Sources:
→ Changelog: Security validation for third-party coding agents
→ Changelog: Dedicated security review command now available in Copilot CLI
→ Changelog: Agentic workflows no longer need a personal access token

6. GitHub Agentic Workflows en préversion publique

Automatisez des tâches de raisonnement — tri des issues, analyse d'échecs CI, mise à jour de documentation — via des fichiers Markdown compilés en YAML Actions standard. Les workflows réutilisent vos runner groups et contraintes de politique existants.

→ Changelog: GitHub Agentic Workflows is now in public preview

7. Facturation à l'usage : nouveau modèle et contrôles budgétaires

Depuis le 1er juin, tous les plans Copilot sont facturés selon les crédits IA consommés, avec un usage inclus par plan. De nouveaux contrôles budgétaires par utilisateur et un runner par défaut au niveau org accompagnent ce changement.

→ Changelog: Updates to GitHub Copilot billing and plans

📊 Le mois en chiffres

  • ~20 % de coûts en moins sur la revue de code Copilot, à qualité équivalente.
  • Des centaines de fuites et vulnérabilités évitées depuis octobre 2025 grâce à la validation automatique du code des agents.
  • 11 catégories de vulnérabilités analysées par la nouvelle commande /security-review du Copilot CLI.
