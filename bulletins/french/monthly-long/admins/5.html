Monthly (Long) #5 · Août 2026 · Admins Edition

🎯 Le fil de cette édition

En août, la gouvernance a été au cœur des évolutions Copilot. Les paramètres gérés d'entreprise s'étendent à de nouveaux clients et scénarios, tandis que la politique globale de modèles et les contrôles MCP offrent aux administrateurs un cadre plus fin pour encadrer l'usage. En parallèle, la mesure progresse : tableau de bord d'impact orienté ROI, ventilation des tokens par modèle et API de métriques enrichie renforcent la visibilité sur la valeur et les coûts. Enfin, plusieurs changements de politiques et de facturation à venir demandent votre attention pour éviter toute interruption côté équipes.

⚠️ Attention

  • Upcoming changes to GitHub Copilot policies and billing — Date : 1 septembre 2026 — Trois changements arrivent, dont la réouverture des inscriptions Business/Enterprise et le passage du niveau d'effort par défaut de la revue de code à Balanced. Vérifiez l'impact dans vos politiques d'entreprise.
  • Upcoming deprecation of MAI-Code-1-Flash — Date : 10 septembre 2026 — Le modèle sera retiré de toutes les expériences Copilot ; migrez vos flux vers MAI-Code-1.1-Flash.
  • Upcoming deprecation of GitHub Spark on github.com — Date : 31 août 2026 — Plus de nouveaux utilisateurs ni de nouvelles apps depuis le 4 août ; l'accès des utilisateurs existants prend fin le 31 août 2026.

🚀 Passez à l'action

  • Passez en revue les changements de politiques et de facturation à venir dans vos politiques d'entreprise.
  • Centralisez la gouvernance de vos clients Copilot avec les paramètres gérés d'entreprise.
  • Cadrez les modèles disponibles avec la gestion de la disponibilité des modèles par défaut.
  • Suivez l'adoption, la valeur et les coûts via les métriques Copilot.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 8 des mises à jour du mois

1. La gouvernance par paramètres gérés d'entreprise s'étend

Les paramètres gérés couvrent désormais JetBrains (plugins, MCP, OpenTelemetry, modes de permission), la spécialisation par équipes d'entreprise et l'auto-mise à jour des marketplaces de plugins. Les administrateurs appliquent des contrôles cohérents et scalables sans centraliser chaque changement.

Sources:
→ Changelog: Enterprise managed settings in GitHub Copilot for JetBrains
→ Changelog: Enterprise team specialization for managed settings
→ Changelog: Enterprise managed settings now support autoupdate for plugin marketplaces

2. Contrôle centralisé des serveurs MCP

Les propriétaires d'entreprise peuvent désormais définir quels serveurs Model Context Protocol les clients Copilot sont autorisés à exécuter, via les clés allowedMcpServers et deniedMcpServers des paramètres gérés. Un levier essentiel pour sécuriser l'usage des agents et intégrations.

→ Changelog: MCP allowlists in enterprise managed settings

3. Politique globale de modèles en disponibilité générale

L'application de la politique de modèles par défaut pour les modèles Copilot en GA est désormais déployée progressivement sur les plans Business et Enterprise. Les administrateurs disposent d'un cadre clair pour aligner les modèles disponibles sur leurs exigences.

→ Changelog: Global model policy generally available

4. La revue de code Copilot élargit sa couverture

Les niveaux d'effort Lite et Balanced passent en disponibilité générale pour ajuster la profondeur d'une revue au risque. La revue couvre aussi désormais les pull requests d'agents (dont Copilot cloud agent) et les très gros changements, avec des motifs de résolution enrichis.

Sources:
→ Changelog: Copilot code review effort levels are generally available
→ Changelog: Copilot code review resolution reasons and expanded capabilities

5. Le tableau de bord d'impact ajoute une section ROI

Le tableau de bord d'impact Copilot intègre une section « Potential return on investment » qui relie la dépense Copilot au volume de pull requests produites. Un argument concret pour objectiver la valeur auprès des directions.

→ Changelog: Copilot impact dashboard adds a return on investment section

6. Plus de finesse sur l'usage et les coûts

Le rapport d'usage détaille désormais les tokens par modèle (entrée, sortie, cache) derrière vos crédits IA, et l'API de métriques d'usage intègre l'activité des agent apps partenaires. La visibilité sur la consommation et l'adoption progresse nettement.

Sources:
→ Changelog: Per-model token breakdown in the usage report
→ Changelog: Copilot usage metrics API adds agent app activity

7. L'onglet Customize de l'app Copilot en disponibilité générale

L'onglet Customize de l'application GitHub Copilot passe en GA et centralise les serveurs MCP, connaissances et flux d'équipe. Un point d'entrée unifié pour aligner Copilot sur les outils déjà en place, utile à gouverner de façon cohérente.

→ Changelog: GitHub Copilot app Customize tab is generally available

8. Nouveaux modèles disponibles dans Copilot

Août a enrichi le catalogue avec Grok 4.6, Gemini 3.7 Flash, Kimi K3 et MAI-Code-1.1-Flash. Combinés à la politique globale de modèles, ces ajouts vous permettent d'offrir plus de choix tout en gardant la main sur ce qui est activé.

Sources:
→ Changelog: Grok 4.6 is now available in GitHub Copilot
→ Changelog: Gemini 3.7 Flash is now available in GitHub Copilot
→ Changelog: Kimi K3 is now available in GitHub Copilot
→ Changelog: MAI-Code-1.1-Flash available in GitHub Copilot
