Monthly (Long) #6 · Août 2026 · Decision-Makers Edition

🎯 Le fil de cette édition

En août, GitHub a orienté Copilot vers deux priorités stratégiques : démontrer la valeur et l'industrialiser à l'échelle de l'entreprise. Le tableau de bord d'impact relie désormais dépense et résultats livrés, tandis que la gouvernance se renforce (politique de modèles généralisée, paramètres managés étendus). En parallèle, l'usage agentique se diffuse dans les outils du quotidien — Slack, Teams, IDE — et le choix de modèles s'élargit. Pour les décideurs, le message est clair : Copilot devient mesurable, pilotable et gouvernable, facilitant la justification de l'investissement et le passage à l'échelle.

⚠️ Attention

  • Upcoming deprecation of MAI-Code-1-Flash — Deadline : 10 septembre 2026 — Migrez vos flux vers MAI-Code-1.1-Flash et vérifiez les politiques de modèles de votre organisation.
  • Upcoming deprecation of GitHub Spark on github.com — Deadline : 31 août 2026 — Exportez les apps existantes avant cette date ; les créations sont déjà fermées.
  • Upcoming changes to GitHub Copilot policies and billing — Action required — Les mises à jour de facturation prennent effet au 1er octobre 2026 pour les clients Business et Enterprise existants ; anticipez avec vos équipes achats.

🏆 Top 8 des mises à jour du mois

1. Relier la dépense Copilot aux résultats livrés

Le tableau de bord d'impact intègre une section « retour sur investissement » qui compare coût et production de pull requests selon la maturité d'adoption. Couplé aux métriques d'usage enrichies, il permet aux décideurs de justifier l'investissement et de cibler les programmes d'adoption.

Sources:
→ Changelog: Copilot impact dashboard adds a return on investment section
→ Changelog: Copilot usage metrics API adds agent app activity
→ Changelog: Per-model token breakdown in the usage report

2. Copilot Code Review, un investissement qui s'accélère

GitHub continue de muscler la revue de code : nouveaux types de PR couverts, motifs de résolution des commentaires et niveaux d'effort généralisés. Un levier direct de qualité et de vélocité, documenté par un retour d'expérience produit transparent.

Sources:
→ Changelog: Copilot code review: Resolution reasons and expanded capabilities
→ Changelog: Copilot code review effort levels are generally available
→ Blog: Better tools made Copilot code review worse. Here's how we actually improved it

3. Une gouvernance prête pour l'échelle de l'entreprise

La politique de modèles globale est désormais généralisée, offrant un contrôle cohérent des modèles autorisés. Les paramètres managés s'étendent (auto-mise à jour des marketplaces, JetBrains, allowlists MCP, spécialisation par équipe), donnant aux administrateurs un cadre unifié et sûr.

Sources:
→ Changelog: Global model policy generally available
→ Changelog: Enterprise managed settings now support autoupdate for plugin marketplaces

4. Copilot au cœur de la collaboration

L'expérience Copilot arrive dans Slack et le travail agentique partagé débarque dans Microsoft Teams. Copilot sort de l'IDE pour s'insérer là où les équipes décident et coordonnent, élargissant son impact au-delà des développeurs.

Sources:
→ Changelog: The new GitHub Copilot experience in Slack
→ Changelog: Shared agentic work with GitHub Copilot in Microsoft Teams

5. Un choix de modèles toujours plus large

Grok 4.6, Gemini 3.7 Flash, Kimi K3 et MAI-Code-1.1-Flash rejoignent Copilot. Cette diversité permet d'optimiser coût, performance et cas d'usage, tout en réduisant la dépendance à un fournisseur unique — un atout stratégique.

Sources:
→ Changelog: Grok 4.6 is now available in GitHub Copilot
→ Changelog: Gemini 3.7 Flash is now available in GitHub Copilot
→ Changelog: Kimi K3 is now available in GitHub Copilot
→ Changelog: MAI-Code-1.1-Flash available in GitHub Copilot

6. Agent plugins 1.0 : une plateforme extensible

Les agent plugins 1.0 arrivent dans VS Code, Copilot CLI et l'application Copilot. Cette standardisation ouvre un écosystème d'extensions, permettant d'adapter Copilot aux outils internes et de capitaliser sur des intégrations réutilisables.

→ Changelog: Agent plugins 1.0 in VS Code, Copilot CLI, and the Copilot app

7. L'application Copilot gagne en maturité

L'onglet Customize passe en disponibilité générale et les automatisations peuvent désormais se déclencher par commentaires. Copilot devient une plateforme d'orchestration configurable, alignée sur les processus de chaque équipe.

Sources:
→ Changelog: GitHub Copilot app Customize tab is generally available
→ Changelog: Trigger Copilot automations with comments

8. L'expérience agentique s'étend à JetBrains

Le harness Copilot est généralisé dans Copilot pour JetBrains, apportant les capacités agentiques aux équipes de cet écosystème. Une couverture IDE élargie qui accélère l'adoption homogène à travers des organisations hétérogènes.

→ Changelog: Copilot harness generally available in Copilot for JetBrains
