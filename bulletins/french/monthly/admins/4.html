Monthly #4 · Juin 2026 · Admins Edition

🎯 Le fil de cette édition

Ce mois-ci, GitHub a consolidé la gouvernance de Copilot à l'échelle de l'entreprise. De nouveaux garde-fous de configuration, un pilotage budgétaire à l'usage et des métriques d'adoption plus complètes convergent vers un objectif : donner aux administrateurs les contrôles, la visibilité et la maîtrise des coûts pour encadrer un développement toujours plus agentique et facturé à la consommation.

⚠️ Attention

  • GPT-4.1 deprecated — Échéance : 1er juin 2026 — Le modèle est retiré de la plupart des expériences Copilot ; activez une alternative prise en charge dans vos politiques de modèles.
  • GPT-5.2 and GPT-5.2-Codex deprecated — Échéance : 5 juin 2026 — Ces modèles sont dépréciés (GPT-5.2 reste disponible pour Copilot code review) ; mettez à jour vos intégrations et politiques.
  • Upcoming deprecation of Opus 4.6 (fast) — Échéance : 29 juin 2026 — Migrez vos workflows vers un modèle pris en charge avant l'interruption de service.

🚀 Passez à l'action

  • Renforcez la gouvernance de vos clients : désactivez l'auto-approbation des commandes (« yolo mode ») et restreignez les places de marché de plugins autorisées.
  • Maîtrisez les dépenses en définissant des budgets de crédits IA par utilisateur au niveau de vos cost centers.
  • Suivez l'adoption et la consommation avec les métriques d'usage de Copilot : crédits IA par utilisateur et PR fusionnées par phase d'adoption.
  • Adaptez Copilot code review à vos règles avec un runner par défaut au niveau organisation et l'exclusion de contenu.
  • Des questions ou besoin d'assistance ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour du mois

1. Premiers garde-fous de gouvernance dans les paramètres gérés par l'entreprise

GitHub ajoute ses premières capacités de gouvernance aux paramètres gérés par l'entreprise : bloquer l'auto-approbation des commandes (« yolo mode ») et restreindre les places de marché de plugins autorisées. Ces contrôles, comme la distribution centralisée de plugins dans VS Code, s'appliquent automatiquement aux clients Copilot Business et Enterprise.

Sources:
→ Changelog: Enterprise-managed settings now support bypass permission controls
→ Changelog: Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI
→ Changelog: Enterprise-managed plugins in VS Code in public preview

2. Budgets de crédits IA par utilisateur pour les cost centers

La facturation à l'usage est désormais active sur tous les plans. GitHub permet de définir un budget de crédits IA par utilisateur au niveau d'un cost center : il suit automatiquement les mouvements d'équipe et peut stopper la consommation avant l'épuisement du pool inclus, sans configuration individuelle.

Sources:
→ Changelog: Per-user AI credit budgets available for cost centers
→ Changelog: Updates to GitHub Copilot billing and plans

3. Des métriques d'usage et d'adoption plus complètes

Les rapports d'usage Copilot gagnent en précision : la télémétrie côté serveur fait remonter des utilisateurs actifs auparavant absents, un nouveau champ expose les crédits IA consommés par utilisateur, et les rapports suivent le total de PR fusionnées par phase d'adoption. Adoption et coûts se mesurent au même endroit.

Sources:
→ Changelog: Copilot usage metrics now include more of your active users
→ Changelog: AI credits consumed per user now in the Copilot usage metrics API
→ Changelog: Track total merges by adoption phase in enterprise and organization reports

4. Copilot code review : nouveaux contrôles et gains d'efficacité

Copilot code review devient plus configurable : runner par défaut et niveau d'analyse « Medium » pilotables au niveau organisation, respect des exclusions de contenu, prise en charge des skills, de MCP et d'AGENTS.md. De nouveaux outils d'exploration réduisent le coût des revues d'environ 20 %, à qualité constante.

Sources:
→ Changelog: Copilot code review: New configurations and controls
→ Changelog: Shape Copilot code review around your team
→ Changelog: Copilot code review: AGENTS.md support and UI improvements
→ Changelog: Copilot code review: Analysis depth and efficiency updates

5. La validation de sécurité s'étend aux agents tiers

La validation de sécurité automatique — CodeQL, base d'avis GitHub et secret scanning — couvre désormais le code produit par les agents tiers (Claude, OpenAI Codex), pas seulement l'agent cloud de Copilot. Activée par défaut et sans licence GitHub Advanced Security, elle applique les mêmes contrôles à chaque ligne générée.

→ Changelog: Security validation for third-party coding agents

📊 Le mois en chiffres

  • ~20 % de coûts en moins sur Copilot code review grâce aux nouveaux outils d'exploration CLI, à qualité de revue constante.
  • Des centaines de fuites et vulnérabilités évitées depuis octobre 2025 par la validation automatique du code, désormais étendue aux agents tiers.
  • 11 catégories de vulnérabilités couvertes par la nouvelle commande /security-review dans Copilot CLI.
