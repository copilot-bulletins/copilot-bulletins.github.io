Biweekly #6 · Du 15 mai au 31 mai 2026 · Admins Edition

🎯 Le fil de cette édition

Cette quinzaine marque une consolidation des leviers de gouvernance administrative pour Copilot. Métriques d'adoption par phase, règles de modèles ciblées par organisation, contrôles de la mémoire au niveau dépôt : les administrateurs disposent maintenant d'une granularité sans précédent. Simultanément, la transition vers la facturation à l'usage entre en vigueur aujourd'hui, changeant fondamentalement la mécanique de contrôle des coûts.

⚠️ Attention

  • GitHub Copilot passe à la facturation à l'usage — Deadline : 1er juin 2026 — La transition est effective aujourd'hui : les crédits IA remplacent les requêtes premium et les expériences de repli disparaissent ; si ce n'est pas fait, configurez vos limites de budget et contrôles de dépenses dès maintenant.

🚀 Passez à l'action

  • Activez les règles de modèles ciblées par organisation pour un contrôle fin des modèles Copilot disponibles dans chaque organisation.
  • Activez la politique Claude Opus 4.8 dans vos paramètres de politiques Copilot pour le rendre disponible aux utilisateurs Business et Enterprise.
  • Explorez les nouveaux champs de phase d'adoption IA dans l'API des métriques pour identifier où concentrer vos efforts d'activation.
  • Configurez vos limites de budget Copilot maintenant que la facturation à l'usage est en vigueur.
  • Des questions ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Cohorts d'adoption IA dans l'API des métriques Copilot

L'API des métriques d'utilisation Copilot classe désormais chaque utilisateur engagé dans une phase d'adoption IA (Phase 0 à 3), selon les surfaces Copilot utilisées sur 28 jours glissants. Les rapports entreprise et organisation exposent ces agrégats pour orienter vos programmes de formation et de déploiement.

→ Changelog: Copilot usage metrics API adds cohorts for AI adoption

2. Contrôle granulaire des modèles par organisation

Les propriétaires d'entreprise peuvent désormais créer des règles ciblées autorisant des modèles Copilot spécifiques à des organisations sélectionnées, dépassant les paramètres globaux de l'entreprise. Une interface rafraîchie centralise la gestion des disponibilités de modèles par défaut sur une seule page.

→ Changelog: Target Copilot models to organizations with model rules

3. Claude Opus 4.8 disponible — activation requise

Claude Opus 4.8, dernier modèle d'Anthropic, est disponible dans GitHub Copilot pour les plans Business et Enterprise. Les administrateurs doivent activer explicitement la politique Claude Opus 4.8 dans les paramètres Copilot de l'entreprise avant que les utilisateurs puissent le sélectionner.

→ Changelog: Claude Opus 4.8 is generally available for GitHub Copilot

4. Contrôles de la mémoire Copilot au niveau dépôt

Les administrateurs de dépôts peuvent désormais désactiver la mémoire Copilot au niveau dépôt depuis les paramètres Copilot du dépôt. Le scope de chaque fait capturé est maintenant clairement indiqué (préférence utilisateur ou fait dépôt) ; la commande /memory est aussi disponible dans le Copilot CLI.

→ Changelog: Copilot Memory has more controls for deletion, scope, and the Copilot CLI

5. GitHub Leader dans le Magic Quadrant Gartner pour la 3e année consécutive

Pour la troisième année consécutive, Gartner positionne GitHub en tête de la capacité d'exécution dans le Magic Quadrant Enterprise AI Coding Agents. Le rapport souligne la maturité opérationnelle de Copilot — gouvernance, sécurité, contrôles d'audit — validant sa pertinence pour les déploiements d'entreprise à grande échelle.

→ Blog: GitHub recognized as a Leader in the Gartner® Magic QuadrantTM for Enterprise AI Coding Agents for the third year in a row
