Biweekly #11 · Du 1er au 14 août 2026 · Admins Edition

🎯 Le fil de cette édition

Cette quinzaine confirme une orientation nette vers la gouvernance à grande échelle et la mesure de la valeur. Les nouveautés donnent aux administrateurs des leviers plus fins pour encadrer les serveurs MCP, déléguer la configuration par équipe et tracer précisément coûts et adoption. L'enjeu : industrialiser le déploiement de Copilot tout en gardant un contrôle opérationnel et une justification budgétaire solides.

⚠️ Attention

  • Upcoming deprecation of GitHub Spark on GitHub.com — Deadline : 31 août 2026 — Depuis le 4 août, aucun nouvel utilisateur ni nouvelle app ; les utilisateurs existants doivent exporter leurs apps avant le 31 août.
  • Upcoming deprecation of MAI-Code-1-Flash — Deadline : 10 septembre 2026 — Migrez vos flux vers MAI-Code-1.1-Flash et vérifiez l'accès au modèle via vos politiques de modèles.
  • Retiring the Copilot Billing Preview app — Action requise — L'app est retirée ; gérez désormais vos dépenses dans les paramètres de facturation.

🚀 Passez à l'action

  • Définissez vos listes d'autorisation MCP au niveau entreprise via les managed settings.
  • Déléguez la configuration par équipe avec la référence des managed settings d'entreprise.
  • Modélisez votre retour sur investissement dans le tableau de bord d'impact Copilot.
  • Définissez un niveau d'effort par défaut pour la revue de code Copilot au niveau de l'organisation.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Contrôlez les serveurs MCP au niveau entreprise

Les propriétaires d'entreprise peuvent désormais autoriser ou bloquer centralement les serveurs MCP via les clés allowedMcpServers et deniedMcpServers des managed settings. Les politiques échouent en mode fermé : une configuration invalide est bloquée par défaut, un vrai gain pour la sécurité et la conformité.

→ Changelog: MCP allowlists in enterprise managed settings

2. Spécialisez les managed settings par équipe

Les administrateurs peuvent maintenant cibler des équipes d'entreprise avec des fichiers de configuration dédiés. Les grandes organisations passent à l'échelle sans centraliser chaque changement ni imposer une politique unique, tout en gardant des garde-fous cohérents.

→ Changelog: Enterprise team specialization for managed settings

3. Un ROI chiffré dans le tableau de bord d'impact

Le tableau de bord d'impact ajoute une section « retour sur investissement potentiel » reliant les dépenses Copilot au volume de pull requests produites. Un sélecteur de salaire recalcule les métriques de coût instantanément, pour justifier l'investissement et cibler l'enablement.

→ Changelog: Copilot impact dashboard adds a return on investment section

4. Niveaux d'effort de la revue de code en disponibilité générale

Les niveaux Lite et Balanced (ex-Low et Medium) sont désormais GA. Vous ajustez la profondeur d'analyse selon la criticité de chaque pull request et définissez des valeurs par défaut au niveau de l'organisation, avec traçabilité du niveau appliqué.

→ Changelog: Copilot code review effort levels are generally available

5. Détail par agent dans l'API de métriques d'usage

L'API de métriques d'usage ajoute un tableau totals_by_3rd_party_agent distinguant l'activité de chaque agent tiers reconnu. Vous pouvez enfin savoir quels agents sont réellement utilisés, par combien de personnes, et suivre l'adoption au fil du temps.

→ Changelog: Copilot usage metrics API adds agent app activity
