Biweekly #7 · Du 1er juin au 14 juin 2026 · Admins Edition

🎯 Le fil de cette édition

Cette quinzaine place la gouvernance et la sécurité au cœur de l'expérience administrateur Copilot. La facturation à l'usage est désormais active, et les leviers de contrôle sur les coûts comme sur la revue de code gagnent en précision. La validation de sécurité s'étend par ailleurs aux agents tiers, donnant aux administrateurs une granularité accrue pour encadrer leur déploiement.

⚠️ Attention

  • GPT-5.2 et GPT-5.2-Codex dépréciés — Action requise — Ces modèles sont retirés de la plupart des expériences Copilot depuis le 5 juin (GPT-5.2 reste disponible pour Copilot code review) ; activez un modèle de remplacement via vos politiques Copilot d'entreprise.
  • GPT-4.1 déprécié — Action requise — Le modèle est retiré de toutes les expériences Copilot depuis le 1er juin ; vérifiez qu'un modèle pris en charge est activé dans vos politiques d'entreprise.

🚀 Passez à l'action

  • Configurez vos budgets au niveau utilisateur pour maîtriser les dépenses maintenant que la facturation à l'usage est active.
  • Définissez vos runners d'organisation pour Copilot code review afin de contrôler où s'exécutent les revues.
  • Standardisez les outils de vos équipes via les standards de plugins d'entreprise dans VS Code et Copilot CLI.
  • Encadrez la mémoire Copilot à l'échelle de l'organisation depuis les contrôles d'administration de Copilot Memory.
  • Des questions ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Facturation à l'usage active : budgets par utilisateur et nouveaux contrôles

La facturation à l'usage est désormais active pour tous les plans. Les administrateurs obtiennent des budgets au niveau utilisateur pour plafonner les dépenses, peuvent définir un runner Actions dédié à Copilot code review, et accèdent au nouveau plan Copilot Max pour les utilisateurs intensifs.

→ Changelog: Updates to GitHub Copilot billing and plans

2. Copilot code review : nouveaux contrôles d'organisation

Copilot code review gagne en contrôle : runners gérés au niveau organisation, prise en charge de l'exclusion de contenu, et suppression de la limite de caractères sur les instructions personnalisées de dépôt. Les équipes ajustent la revue à leurs exigences de gouvernance et de confidentialité.

→ Changelog: Copilot code review: New configurations and controls

3. Validation de sécurité pour les agents de code tiers

Le code généré par des agents tiers (Claude, OpenAI Codex) reçoit désormais la même validation automatique que l'agent cloud Copilot : analyse CodeQL, vérification des dépendances via la GitHub Advisory Database et détection de secrets. Une couche de sécurité homogène, quel que soit l'agent.

→ Changelog: Security validation for third-party coding agents

4. Plugins gérés par l'entreprise dans VS Code

Les administrateurs d'entreprise peuvent distribuer et imposer des plugins Copilot — agents personnalisés, compétences, hooks et configurations MCP — à l'ensemble des clients VS Code (version 1.122) et Copilot CLI. Une gouvernance centralisée qui accélère l'onboarding et standardise les pratiques.

→ Changelog: Enterprise-managed plugins in VS Code in public preview

5. Copilot Memory : préférences utilisateur et contrôles admin pour Business et Enterprise

Copilot Memory déploie en préversion publique les préférences au niveau utilisateur (style de communication, stack, conventions Git) pour Copilot Business et Enterprise, accompagnées de nouveaux contrôles d'administration. Les administrateurs encadrent ainsi la gouvernance de la mémoire à l'échelle de l'organisation.

→ Changelog: Copilot Memory supports user preferences for Business, Enterprise

📌 Également dans cette édition

  • Adaptez Copilot code review à votre équipe — Les compétences d'agent et MCP enrichissent les revues, et un nouveau palier d'analyse « medium » ajuste la profondeur à la complexité du changement.
  • Les workflows agentiques n'ont plus besoin de jeton d'accès personnel — Ils utilisent désormais le GITHUB_TOKEN d'Actions, éliminant les risques de sécurité liés aux PAT à longue durée de vie.
  • GitHub Agentic Workflows passe en préversion publique — Automatisez le tri d'issues ou l'analyse d'échecs CI en Markdown, compilé en YAML Actions réutilisant vos runner groups et contraintes de politique.
  • Commande de revue de sécurité dédiée dans Copilot CLI — La commande /security-review repère les vulnérabilités courantes dans vos modifications locales avant le commit.
