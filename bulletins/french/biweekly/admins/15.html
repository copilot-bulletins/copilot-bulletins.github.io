Biweekly #15 · Du 1er octobre au 14 octobre 2026 · Admins Edition

🎯 Le fil de cette édition

Cette quinzaine place la gouvernance au premier plan. GitHub a renforcé l'arsenal des administrateurs : application forcée des paramètres gérés, attribution télémétrie granulaire, contrôles de facturation et de licence pour la revue de code, détection de secrets dédiée et fiabilisation des métriques d'usage. Pour les administrateurs, cela se traduit par davantage de leviers pour imposer vos politiques, attribuer l'activité et maîtriser les coûts à l'échelle de l'entreprise.

⚠️ Attention

  • Selected models in GitHub Copilot deprecated — Action requise — Certains modèles ont été dépréciés le 2 octobre 2026 dans toutes les expériences Copilot. En tant qu'administrateur Copilot Enterprise, vérifiez vos politiques de modèles et activez des modèles alternatifs depuis vos politiques d'organisation.

🚀 Passez à l'action

  • Imposez l'application immédiate de vos politiques en forçant le rafraîchissement des paramètres au démarrage via le déploiement des paramètres gérés d'entreprise.
  • Révisez les nouveaux contrôles de facturation et de licence de la revue de code dans vos politiques d'organisation.
  • Mettez à jour vos IDE pour restaurer l'attribution de l'activité agent dans vos métriques d'usage Copilot.
  • Configurez l'attribution d'activité et les classes de capture télémétrie dans vos paramètres gérés d'entreprise.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Application renforcée des paramètres gérés d'entreprise

Les administrateurs peuvent désormais exiger que les clients Copilot récupèrent les paramètres serveur à jour au démarrage plutôt qu'une politique en cache. Un nouveau réglage impose aussi une version minimale du client, garantissant qu'un changement de politique s'applique avant toute utilisation de Copilot.

→ Changelog: Enterprise managed settings enforcement updates

2. Nouveaux contrôles de facturation et de licence pour la revue de code

La revue de code Copilot ajoute des contrôles pour administrateurs d'organisation : facturer les demandes à l'organisation propriétaire du dépôt plutôt qu'au quota du membre, et restreindre les demandes de revue aux seuls utilisateurs disposant d'une licence fournie par votre organisation.

→ Changelog: Copilot code review: new organization billing options and controls

3. Attribution utilisateur et capture télémétrie configurable

Les administrateurs peuvent désormais attribuer l'activité Copilot à un utilisateur sans collecter ses prompts, réponses ou contenus d'outils. Cinq classes de capture additionnelles, désactivées par défaut, offrent un contrôle fin pour vos usages d'audit et de conformité.

→ Changelog: Client telemetry: user attribution and configurable capture

4. Modèle dédié à la détection de secrets exposés

GitHub introduit un modèle affiné pour la détection de secrets, exploité dans les alertes de secret scanning, la push protection et les revues de sécurité Copilot. Il lit le code environnant pour repérer des identifiants probables, y compris des mots de passe sans format de jeton reconnaissable.

→ Changelog: Purpose-built model for leaked secret detection

5. Restauration de l'activité agent dans les métriques d'usage

Un correctif rétablit l'attribution de l'activité agent dans le tableau de bord et l'API des métriques d'usage, déjà disponible dans VS Code. L'activité perdue n'étant pas récupérable, mettez à jour vos IDE dès que la version corrigée est disponible.

→ Changelog: Update your IDE to restore agent activity in Copilot usage metrics
