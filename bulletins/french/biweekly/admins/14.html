Biweekly #14 · Du 15 septembre au 30 septembre 2026 · Admins Edition

🎯 Le fil de cette édition

Cette quinzaine a été dominée par la gouvernance et le pilotage à grande échelle. GitHub renforce le contrôle administratif sur l'activation des fonctionnalités, la validation des paramètres gérés et la mesure de l'adoption. Pour les administrateurs, l'enjeu est clair : configurer les politiques par défaut dès maintenant et exploiter des métriques plus fines pour piloter le déploiement de Copilot.

⚠️ Attention

  • Dépréciation de plusieurs modèles Copilot à la mi-octobre — Échéance : 19 octobre 2026 — Gemini 3.7 Flash, GPT-5.5, GPT-5.4, GPT-5.4 mini, GPT-5 mini et Grok 4.5 seront retirés. Les alternatives suggérées sont activées par défaut pour Business et Enterprise, sauf si le défaut global a été désactivé. Vérifiez vos politiques de disponibilité des modèles.

🚀 Passez à l'action

  • Configurez la nouvelle politique d'activation par défaut depuis vos politiques d'entreprise Copilot pendant la fenêtre de 28 jours.
  • Validez vos fichiers de paramètres gérés avec le déploiement des managed settings.
  • Suivez l'adoption des fonctionnalités via le tableau de bord d'impact Copilot.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Activation par défaut des fonctionnalités pour Business et Enterprise

GitHub introduit une politique globale par défaut pour les fonctionnalités Copilot généralement disponibles. Pendant 28 jours, vous pouvez la configurer sans impact sur les utilisateurs, depuis la page « AI Controls ». Préparez votre posture de gouvernance avant son entrée en vigueur.

→ Changelog: Default Enablement of Copilot features for Copilot Business and Enterprise

2. Validateur intégré des paramètres gérés d'entreprise

Un validateur détecte désormais le JSON malformé, les configurations non prises en charge et les mappings d'équipe invalides qui empêchent l'application des politiques. Chaque erreur identifie le fichier et le chemin JSON concernés, pour corriger rapidement et garantir l'application effective des règles.

→ Changelog: Enterprise managed settings in-product validator

3. L'API de métriques d'usage ajoute les étapes de revue des pull requests

Les rapports de métriques d'usage détaillent désormais le temps passé par les pull requests à chaque étape de revue : médiane et 90e percentile du temps « prêt pour revue » à première revue, puis à revue finale, puis au merge. Un indicateur précieux pour piloter l'efficacité des flux.

→ Changelog: Usage metrics API adds pull request review stages

4. Le tableau de bord d'impact affiche l'engagement par fonctionnalité

Le tableau de bord d'impact Copilot montre désormais combien d'utilisateurs actifs exploitent régulièrement chaque fonctionnalité clé. Les administrateurs identifient vite les expériences largement adoptées et celles nécessitant plus d'activation, avec la même ventilation sur 28 jours exposée via les API.

→ Changelog: Copilot impact dashboard now shows feature engagement

5. L'autofix agentique s'appuie sur Copilot Memory

Pour les clients ayant activé Copilot Memory, l'autofix agentique consulte les mémoires existantes pour résoudre les alertes de sécurité et enregistre les correctifs comme motifs réutilisables. Ces mémoires diffusent vos pratiques de développement sécurisé à d'autres fonctionnalités Copilot.

→ Changelog: Agentic autofix now uses Copilot Memory
