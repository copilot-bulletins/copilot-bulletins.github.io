Biweekly #16 · Du 15 octobre au 31 octobre 2026 · Admins Edition

🎯 Le fil de cette édition

Cette quinzaine, marquée par GitHub Universe, la gouvernance de Copilot passe du réglage manuel à la configuration programmable. Les politiques s'appliquent par défaut, se pilotent par API et les métriques deviennent nettement plus fines. Pour les administrateurs, l'enjeu est de vérifier dès maintenant les paramètres hérités avant que les nouveaux usages agentiques ne se généralisent.

⚠️ Attention

  • Upcoming deprecation of selected GitHub Copilot models in mid-November — Deadline: 16 novembre 2026 — Claude Opus 4.8, Claude Opus 5 et GPT-5.6 Terra seront retirés ; vérifiez que les alternatives sont activées dans vos politiques de modèles.
  • GitHub Copilot models deprecated on October 19, 2026 — Action required — GPT-5.5, GPT-5.4, GPT-5 mini, Grok 4.5 et Gemini 3.7 Flash ne sont plus disponibles ; mettez à jour vos workflows en consultant les modèles pris en charge.

🚀 Passez à l'action

  • Contrôlez votre réglage sous AI Controls → Copilot → Default policy for new features, en vous appuyant sur la documentation sur la disponibilité par défaut.
  • Automatisez la gestion des modèles avec les endpoints REST des AI controls.
  • Définissez les marketplaces approuvées et les plugins requis ou bloqués via les paramètres gérés par l'entreprise.
  • Analysez les nouveaux champs totals_by_client et totals_by_skill dans les données des métriques d'usage Copilot.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Copilot inclus dans GitHub Enterprise

Les entreprises accompagnées par une équipe GitHub ou Microsoft peuvent désormais inclure Copilot pour chaque licence GitHub Enterprise. Fini la gestion des sièges : l'usage IA est mesuré dès la première requête contre le budget de l'entreprise, avec vos politiques et alertes existantes.

→ Changelog: GitHub Enterprise now includes access to GitHub Copilot

2. La politique par défaut des fonctionnalités s'applique

Déployée jusqu'au 26 octobre, la politique globale configure automatiquement les fonctionnalités GA restées « Unconfigured » (Enabled, Disabled ou Let organizations decide). Vos choix explicites sont conservés et les fonctionnalités en preview restent en opt-in.

→ Changelog: Global default for Copilot features generally available

3. Politiques de modèles pilotables par API

Des endpoints GET et PATCH, désormais GA, permettent de lire et modifier les politiques de modèles au niveau entreprise, équipes d'entreprise, agent apps et organisations. Idéal pour industrialiser la gouvernance et déléguer le contrôle des modèles.

→ Changelog: Copilot model policy API for enterprise, orgs, and teams

4. Des métriques d'usage beaucoup plus précises

L'API de métriques affiche désormais le nom de vos skills, agents personnalisés, serveurs MCP et plugins (jusqu'à 25 entrées), ainsi qu'un nouveau tableau totals_by_client couvrant aussi des outils tiers comme OpenCode ou Claude Code.

Sources:
→ Changelog: Custom skills, agents, and MCP servers in usage metrics API
→ Changelog: Usage metrics API adds usage from tools like OpenCode

5. Contrôle des plugins à l'échelle de l'entreprise

Les administrateurs peuvent exiger ou bloquer des plugins et restreindre l'installation à des marketplaces approuvées dans VS Code, Copilot CLI et l'app Copilot. Les paramètres gérés priment sur les choix des dépôts et des utilisateurs.

→ Changelog: Repository plugin defaults and enterprise plugin controls generally available
