Biweekly #17 · Du 1er novembre au 14 novembre 2026 · Admins Edition

🎯 Le fil de cette édition

Cette quinzaine, Copilot devient plus pilotable par programmation. Les réglages de revue de code, l'attribution des licences et la qualité des métriques sont désormais accessibles par API. Pour les administrateurs, cela permet d'automatiser la gouvernance à grande échelle, de fiabiliser les tableaux de bord d'adoption et de mieux maîtriser les modèles utilisés, notamment leurs conditions de rétention des données.

⚠️ Attention

  • Upcoming deprecation of selected GitHub Copilot models in December — Deadline: 14 décembre 2026 — Claude Fable 5, Claude Haiku 4.5, Gemini 3.8 Flash, Gemini 4 Argon, Grok 4.6 et Kimi K3 seront retirés. Vérifiez que les modèles de remplacement sont activés dans vos politiques de modèles.

🚀 Passez à l'action

  • Automatisez l'activation et le niveau d'effort de la revue de code Copilot via l'API de configuration de la revue de code.
  • Confiez l'attribution des licences à une GitHub App grâce aux endpoints REST de gestion des utilisateurs Copilot.
  • Identifiez les utilisateurs aux versions d'IDE obsolètes en consultant les versions minimales prises en charge par les métriques.
  • Évaluez la politique Claude Fable 5.2 et ses conditions de rétention avant activation dans les politiques de votre entreprise.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. La revue de code Copilot se configure entièrement par API

Les réglages de la revue de code sont désormais gérables via REST et GraphQL, de la politique d'entreprise jusqu'au dépôt. Les réglages imposés par l'entreprise ne peuvent pas être contournés, et les revues de Copilot sont identifiables grâce à des champs d'attribution explicites.

→ Changelog: Copilot code review: API management and review overview updates

2. Attribution des licences Copilot via GitHub Apps

Les GitHub Apps d'entreprise peuvent appeler les API de gestion des licences Copilot pour attribuer des postes aux utilisateurs et équipes d'entreprise. Une nouvelle permission granulaire, Enterprise Copilot license management, évite de recourir à des jetons personnels.

→ Changelog: GitHub App support for Enterprise Copilot seat management

3. Des métriques d'usage plus fiables

L'API de métriques signale désormais les utilisateurs sans télémétrie client ou utilisant des IDE et extensions sous les versions minimales. Vous pouvez ainsi cibler les postes à mettre à jour et combler les lacunes de vos rapports sans ouvrir de ticket.

→ Changelog: Usage metrics API flags telemetry and version gaps

4. Mesurer l'impact réel de la revue de code

Les rapports par dépôt indiquent combien de commentaires de Copilot ont été pris en compte, ventilés par sévérité, type et personnalisation. Un taux de prise en compte par dépôt permet d'objectiver la valeur de la revue de code automatisée.

→ Changelog: Usage metrics API adds code review details and addressed rate

5. Claude Fable 5.2 : une politique à évaluer

Claude Fable 5.2 est disponible, mais sa politique est désactivée par défaut. Ce modèle requiert une rétention des données par Anthropic ; l'activer vaut acceptation. Une exemption de rétention nulle est possible pour certaines entreprises éligibles jusqu'à fin 2026.

→ Changelog: Claude Fable 5.2 in GitHub Copilot
