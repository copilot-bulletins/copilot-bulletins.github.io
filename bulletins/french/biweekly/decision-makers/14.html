Biweekly #14 · Du 15 septembre au 30 septembre 2026 · Decision-Makers Edition

🎯 Le fil de cette édition

Cette quinzaine confirme la stratégie de GitHub : offrir le choix des meilleurs modèles tout en outillant les dirigeants pour en mesurer la valeur. L'arrivée de nouveaux modèles de pointe, l'activation par défaut des fonctionnalités et des tableaux de bord d'adoption enrichis traduisent une même priorité : accélérer le temps de création de valeur et rendre le retour sur investissement de Copilot plus visible et plus pilotable à l'échelle de l'entreprise.

⚠️ Attention

  • Dépréciation de certains modèles Copilot mi-octobre — Date limite : 19 octobre 2026 — Plusieurs modèles seront retirés de toutes les expériences Copilot. Vérifiez vos usages et planifiez la bascule via les modèles pris en charge.

🚀 Passez à l'action

  • Mesurez l'adoption réelle de vos équipes avec le tableau de bord d'impact Copilot.
  • Anticipez la fenêtre de 28 jours de l'activation par défaut en révisant vos politiques d'organisation.
  • Maîtrisez vos coûts et la gouvernance financière avec les budgets Copilot.
  • Évaluez les nouveaux modèles de pointe parmi les modèles pris en charge.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Mesurer l'adoption pour piloter le retour sur investissement

Le tableau de bord d'impact Copilot montre désormais combien d'utilisateurs actifs exploitent régulièrement les fonctionnalités clés. Les dirigeants identifient d'un coup d'œil les usages largement adoptés et ceux à accompagner, pour orienter la formation et maximiser la valeur dégagée.

→ Changelog: Copilot impact dashboard now shows feature engagement

2. Activation par défaut des fonctionnalités pour Business et Enterprise

Une nouvelle politique active par défaut les fonctionnalités Copilot en disponibilité générale, avec une fenêtre de 28 jours pour ajuster les paramètres. Résultat : un déploiement plus rapide des capacités à forte valeur, et moins de délais avant que les équipes n'en bénéficient.

→ Changelog: Default enablement of Copilot features for Copilot Business and Enterprise

3. Project HydraFusion : qualité de pointe par orchestration multi-modèles

HydraFusion arrive dans Visual Studio Code et l'application GitHub Copilot. Plutôt qu'un modèle unique, il orchestre plusieurs modèles pour viser une qualité maximale. Un signal clair de la stratégie de GitHub pour rester à la frontière de la performance IA.

Sources:
→ Blog: Project HydraFusion: frontier quality via multi-model orchestration
→ Changelog: HydraFusion in VS Code and the GitHub Copilot app

4. Un choix de modèles de pointe qui s'élargit

La quinzaine ajoute GPT-6 Sol et GPT-6 Luna, Claude Opus 5.5 et Claude Sonnet 5.5. Cette diversité donne à vos équipes le bon modèle pour chaque tâche et renforce la liberté de choix, un avantage stratégique face à la concurrence.

Sources:
→ Changelog: OpenAI's GPT-6 Sol and GPT-6 Luna now available
→ Changelog: Claude Opus 5.5 is now available in GitHub Copilot
→ Changelog: Claude Sonnet 5.5 in GitHub Copilot

5. Copilot code review : plus de contrôle au niveau entreprise

La revue de code Copilot propose désormais des configurations personnelles élargies et un paramètre par défaut au niveau entreprise. De quoi généraliser une revue de qualité constante à grande échelle, pour accélérer les livraisons sans sacrifier la fiabilité.

→ Changelog: Copilot code review: more ways to request and configure reviews
