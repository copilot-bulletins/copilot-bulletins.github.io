Biweekly #11 · Du 1er août au 14 août 2026 · Decision-Makers Edition

🎯 Le fil de cette édition

Cette quinzaine confirme un basculement stratégique : Copilot cesse de se mesurer à l'adoption pour se mesurer à l'impact. GitHub relie désormais la dépense au retour sur investissement, ouvre ses métriques à l'activité des agents et renforce la gouvernance à l'échelle de l'entreprise. Pour les décideurs, Copilot devient une plateforme pilotable financièrement et justifiable auprès des directions.

⚠️ Attention

  • Upcoming deprecation of GitHub Spark on github.com — Deadline : 31 août 2026 — Depuis le 4 août, aucun nouvel utilisateur ni application ; les utilisateurs existants doivent exporter leurs applications avant la fermeture. Anticipez la gestion de Spark.
  • Upcoming deprecation of MAI-Code-1-Flash — Deadline : 10 septembre 2026 — Le modèle sera retiré de toutes les expériences Copilot au profit de MAI-Code-1.1-Flash. Prévoyez la bascule dans vos équipes.

🚀 Passez à l'action

  • Mesurez la valeur créée en explorant la section retour sur investissement du tableau de bord d'impact via l'analyse de l'usage et de l'adoption.
  • Standardisez votre gouvernance à grande échelle avec les paramètres gérés par l'entreprise.
  • Intégrez l'activité des agents à votre pilotage grâce aux métriques d'usage Copilot.
  • Des questions ou besoin d'accompagnement ? Contactez votre équipe GitHub, nous sommes là pour vous aider.

🏆 Top 5 des mises à jour

1. Le tableau de bord d'impact chiffre enfin le ROI

Le tableau de bord d'impact ajoute une section « retour sur investissement potentiel » qui relie directement votre dépense Copilot au volume de pull requests produites. Un argument concret pour justifier l'investissement auprès des directions et arbitrer les budgets.

→ Changelog: Copilot impact dashboard adds a return on investment section

2. Les métriques d'usage intègrent l'activité des agents

L'API de métriques d'usage rapporte désormais l'activité des agents partenaires (Claude, Codex...), ventilée par agent, dans les rapports entreprise et organisation. Une visibilité essentielle pour piloter l'adoption réelle de l'écosystème agentique et son coût.

→ Changelog: Copilot usage metrics API adds agent app activity

3. Agent Plugins 1.0 : un standard ouvert multi-éditeurs

GitHub publie Agent Plugins 1.0, un standard ouvert qui packagent compétences et serveurs MCP en un plugin unique, gouverné indépendamment d'un éditeur. Soutenu par AWS, Microsoft, OpenAI, Vercel et Google, il réduit le risque de dépendance à un fournisseur.

→ Changelog: Agent Plugins 1.0 in VS Code, Copilot CLI, and the Copilot app

4. Gouvernance ciblée par équipe pour les grandes entreprises

Les administrateurs peuvent désormais adapter les paramètres gérés à des équipes spécifiques via des fichiers de configuration dédiés. Les grandes organisations passent à l'échelle sans goulot d'étranglement central, tout en respectant les garde-fous définis.

→ Changelog: Enterprise team specialization for managed settings

5. Les niveaux d'effort de la revue de code en disponibilité générale

Les niveaux d'effort Lite et Balanced de la revue de code Copilot passent en disponibilité générale. Ils ajustent la profondeur de l'analyse au risque de chaque pull request, optimisant le rapport qualité/coût de la revue automatisée.

→ Changelog: Copilot code review effort levels are generally available
