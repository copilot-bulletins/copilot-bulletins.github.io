Monthly (Long) #7 · Septiembre 2026 · Decision-Makers Edition

🎯 El hilo de esta edición

Septiembre consolidó un mensaje estratégico para quien decide: Copilot deja de medirse por adopción y pasa a medirse por impacto gobernado. GitHub conectó la medición del retorno —panel de impacto con uso de funciones, métricas por etapas de revisión— con una gobernanza de costes más fina y una habilitación de funciones por defecto que acelera el despliegue sin perder control. En paralelo, el catálogo de modelos de frontera se amplió y la orquestación multimodelo apunta a calidad superior con menor coste. La dirección es clara: escalar la IA agéntica con visibilidad de ROI, elección de modelo y control financiero.

⚠️ Atención

  • Próxima retirada de modelos seleccionados en octubre — Fecha límite: 19 de octubre de 2026 — Revise qué modelos usan sus equipos y planifique la migración desde la gestión de disponibilidad de modelos.

🚀 Pasa a la acción

  • Mida el retorno con el panel de impacto y las métricas de uso de Copilot.
  • Contenga el gasto con presupuestos por usuario y la gestión de solicitudes de aumento de presupuesto.
  • Optimice coste y calidad activando la selección automática de modelo.
  • Gobierne el despliegue con las políticas de empresa y la revisión de código de Copilot.
  • ¿Preguntas o necesita apoyo? Contacte con su equipo de GitHub, estamos aquí para ayudar.

🏆 Top 8 de actualizaciones del mes

1. Medir el retorno: adopción de funciones y métricas por etapas

El panel de impacto ahora muestra qué funciones usan de forma recurrente los usuarios activos, y la API de métricas añade los tiempos por etapa de revisión y los agentes de VS Code. Para la dirección, esto traduce el gasto en IA en evidencia concreta de uso y productividad.

Sources:
→ Changelog: Copilot impact dashboard now shows feature engagement
→ Changelog: Usage metrics API adds pull request review stages
→ Changelog: Add VS Code agents to Copilot usage metrics

2. El catálogo de modelos de frontera se amplía

Septiembre incorporó una oferta excepcional de modelos de última generación —GPT-6 Astra en disponibilidad general, GPT-6 Sol y Luna, Claude Opus 5.5 y Sonnet 5.5, y Grok 4.7—. Más elección significa optimizar calidad, coste y latencia según cada caso de uso, sin dependencia de un único proveedor.

Sources:
→ Changelog: GPT-6 Astra is generally available in GitHub Copilot
→ Changelog: OpenAI's GPT-6 Sol and GPT-6 Luna now available
→ Changelog: Claude Opus 5.5 is now available in GitHub Copilot
→ Changelog: Grok 4.7 is now available in GitHub Copilot

3. La revisión de código con Copilot gana madurez

La revisión de código evoluciona hacia un flujo autónomo gobernable: ahora puede aprobar pull requests, autorresuelve sus propias sugerencias con mayor inteligencia y ofrece nuevas formas de solicitar y configurar revisiones. Un acelerador directo de la velocidad de entrega y la calidad del código.

Sources:
→ Changelog: Copilot code review can now approve pull requests
→ Changelog: Copilot code review: an improved review experience
→ Changelog: Copilot code review: more ways to request and configure reviews

4. Reapertura de altas para Copilot Business y Enterprise

GitHub reabre gradualmente los registros de Copilot Business y Enterprise para clientes que pagan con tarjeta o PayPal. Una señal de demanda sostenida y una oportunidad para equipos que esperaban comenzar a escalar su adopción empresarial.

→ Changelog: Reopening Copilot Business and Enterprise signups

5. Gobernanza de costes más fina

El control financiero madura: fechas de caducidad para presupuestos individuales, disponibilidad general de las solicitudes de aumento de presupuesto y ajuste de coste y calidad en la selección automática de modelo. La dirección obtiene instrumentos concretos para contener y justificar el gasto en IA.

Sources:
→ Changelog: Set an expiration date for individual user budgets
→ Changelog: Copilot budget increase requests are generally available
→ Changelog: Configure cost and quality in Copilot auto model selection

6. HydraFusion: calidad de frontera con orquestación multimodelo

El proyecto HydraFusion orquesta varios modelos para alcanzar calidad de frontera reduciendo el coste estimado frente a una línea base de referencia. Para quien decide, apunta a la ecuación clave de la IA a escala: más calidad por unidad de gasto.

Sources:
→ Blog: Project HydraFusion: frontier quality via multi-model orchestration
→ Changelog: HydraFusion in VS Code and the GitHub Copilot app

7. Despliegue por defecto con gobernanza de empresa

Una nueva política global habilita por defecto las funciones en disponibilidad general, mientras los ajustes gestionados admiten cualquier modelo por defecto y permisos granulares para operaciones de agentes. Se acelera la puesta en producción sin renunciar al control centralizado.

Sources:
→ Changelog: Default enablement of Copilot features for Copilot Business and Enterprise
→ Changelog: Enterprise managed settings support any default model
→ Changelog: Enterprise managed permissions for GitHub Copilot agent operations

8. Copilot llega a más flujos de trabajo en Slack y Teams

Copilot en Slack y Microsoft Teams ofrece más contexto, más control y un camino más claro de la conversación al trabajo en GitHub. Lleva la IA a los espacios donde los equipos ya colaboran, ampliando el alcance del valor más allá del IDE.

→ Changelog: Updates to GitHub Copilot for Slack and Microsoft Teams

  • Local sandboxing in the GitHub Copilot app — Ejecución de agentes en entornos locales aislados con mayor seguridad.
  • OpenTelemetry in the GitHub Copilot app — Observabilidad estándar para supervisar la actividad agéntica.
  • Agentic autofix now uses Copilot memory — Correcciones de seguridad más contextuales y consistentes.
  • Faster C# code intelligence with whole-codebase indexing — Mejor comprensión del código a escala de repositorio completo.
