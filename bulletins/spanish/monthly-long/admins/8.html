Monthly (Long) #8 · Octubre 2026 · Admins Edition

🎯 El hilo de esta edición

Octubre traslada el centro de la administración de Copilot de las licencias al consumo. El nuevo modelo incluido en GitHub Enterprise, la facturación de code review a nivel de organización y los límites de créditos en Automations convierten el presupuesto en la palanca principal de gestión.

Al mismo tiempo, la gobernanza se vuelve más programable y verificable: APIs de políticas de modelos, managed settings que fallan en modo cerrado, sandboxing local y métricas que identifican cada herramienta y personalización. Para los administradores, el reto es menos habilitar funciones y más definir políticas, presupuestos y visibilidad desde el principio.

⚠️ Atención

  • Upcoming deprecation of selected GitHub Copilot models in mid-November — Fecha límite: 16 de noviembre de 2026 — Claude Opus 4.8, Claude Opus 5 y GPT-5.6 Terra serán retirados; si desactivó el global default, habilite las alternativas en la lista de modelos compatibles.
  • Update your IDE to restore agent activity in Copilot usage metrics — Acción requerida — La actividad de agentes en versiones de IDE afectadas no se puede recuperar; despliegue las versiones corregidas y revise las métricas de uso de Copilot.

🚀 Pasa a la acción

  • Revise el nuevo modelo de acceso y facturación en Qué cambia con GitHub Enterprise y Copilot.
  • Confirme su política global en AI Controls con la guía de disponibilidad predeterminada de funciones y modelos.
  • Refuerce sus políticas con forceRemoteSettingsRefresh, sandboxing y permisos asistidos mediante los enterprise managed settings.
  • Decida cómo se factura Copilot code review y quién puede solicitarlo en la configuración de code review.
  • Active la comparación sectorial (opcional) en el dashboard de impacto de Copilot.

🏆 Top 8 de actualizaciones del mes

1. Copilot incluido en GitHub Enterprise: gestionar presupuesto, no licencias

Las empresas que trabajan con un equipo de cuentas de GitHub o Microsoft pueden incluir Copilot para cada usuario licenciado de GitHub Enterprise. El uso de IA se mide desde la primera solicitud contra el presupuesto; si se agota, se conservan las sugerencias de código.

→ Changelog: GitHub Enterprise now includes access to GitHub Copilot

2. Copilot Fusion y control programático de modelos

Copilot Fusion (GA) enruta y orquesta modelos por tarea, usando solo los habilitados en sus políticas. Los administradores pueden fijarlo como predeterminado y gestionar políticas de modelos por API a nivel de empresa, equipos, apps y organizaciones.

Sources:
→ Changelog: Route and orchestrate models with GitHub Copilot Fusion
→ Changelog: Copilot model policy API for enterprise, orgs, and teams

3. Políticas predeterminadas y managed settings más estrictos

La política global para funciones GA ya se aplica a los ajustes no configurados, respetando las decisiones explícitas. Además, los clientes pueden exigir políticas actualizadas al iniciar, fallando en modo cerrado, y se introducen versiones mínimas de cliente.

Sources:
→ Changelog: Global default for Copilot features generally available
→ Changelog: Enterprise managed settings enforcement updates

4. Métricas de uso más completas y comparables

La API de métricas muestra ahora los nombres de skills, agentes personalizados y servidores MCP internos, y añade uso por cliente (OpenCode, Claude Code, Codex...). El dashboard de impacto incorpora comparaciones sectoriales opcionales con empresas similares.

Sources:
→ Changelog: Custom skills, agents, and MCP servers in usage metrics API
→ Changelog: Usage metrics API adds usage from tools like OpenCode
→ Changelog: Industry comparisons in the Copilot impact dashboard

5. Copilot code review: facturación, control de acceso y aprobaciones

Las organizaciones pueden facturar las revisiones a su centro de costos y limitar las solicitudes a licencias propias. Code review se integra vía API, añade el nivel Max (preview) y las aprobaciones de Copilot son GA.

Sources:
→ Changelog: Copilot code review: New organization billing options and controls
→ Changelog: Copilot code review: API support and new default effort level
→ Changelog: Copilot code review: Merge with confidence with Max and approvals

6. Remediación agéntica y detección de secretos con IA

El agentic autofix (GA) corrige alertas de code scanning y valida con CodeQL antes de abrir un PR; requiere habilitar una nueva política de Advanced Security. Un modelo especializado amplía la detección de secretos a push protection y revisiones de Copilot.

Sources:
→ Changelog: Agentic autofix for code scanning alerts general availability
→ Changelog: Purpose-built model for leaked secret detection

7. Agentes locales con límites definidos por la empresa

El sandboxing local (GA) restringe archivos, red y credenciales para comandos ejecutados por Copilot, y puede imponerse vía managed settings. Los permisos asistidos (GA) permiten bloquear "Allow All" y definir el modo de aprobación predeterminado.

Sources:
→ Changelog: Local sandboxing for GitHub Copilot now generally available
→ Changelog: GitHub Copilot assisted permissions generally available

8. Telemetría con atribución de usuario configurable

Los administradores pueden atribuir la actividad de Copilot en OpenTelemetry a usuarios sin capturar prompts ni respuestas. Cinco clases de captura (prompts, respuestas, argumentos y salidas de herramientas, detalle de políticas) se controlan por separado y están desactivadas por defecto.

→ Changelog: Client telemetry user attribution and configurable capture
