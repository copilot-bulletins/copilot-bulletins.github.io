Monthly (Long) #7 · Septiembre 2026 · Admins Edition

🎯 El hilo de esta edición

Septiembre giró en torno al control empresarial. GitHub reforzó el gobierno de Copilot con políticas por defecto configurables para funciones nuevas, permisos gestionados para operaciones de agentes y exclusiones de contenido en la app y la CLI. En paralelo, la observabilidad maduró: el panel de impacto y las APIs de métricas ahora revelan qué funciones se adoptan de verdad. Para los equipos de administración, el mensaje es claro: hay más palancas para definir barreras, medir la adopción real y gobernar el gasto antes de abrir el acceso de forma masiva.

⚠️ Atención

  • Próxima retirada de modelos seleccionados de GitHub Copilot a mediados de octubre — Fecha límite: 19 de octubre de 2026 — Actualiza tus flujos e integraciones a modelos compatibles; revisa las alternativas sugeridas en el resumen de modelos.

🚀 Pasa a la acción

  • Configura la nueva política por defecto para funciones nuevas durante la ventana de 28 días desde la página "AI Controls", según la documentación de disponibilidad por defecto.
  • Define barreras para las operaciones de agentes con los permisos gestionados de funciones agénticas.
  • Activa las exclusiones de contenido para proteger el código sensible en flujos agénticos.
  • Revisa la adopción real por función con las métricas de uso de Copilot.
  • ¿Dudas o necesitas apoyo? Contacta con tu equipo de GitHub, estamos aquí para ayudarte.

🏆 Top 8 de actualizaciones del mes

1. Política por defecto para funciones nuevas en empresa y organización

Una nueva política global permite decidir si las funciones de Copilot ya disponibles se activan automáticamente para tus usuarios. Durante 28 días puedes configurarla sin que afecte al acceso, para preparar tu postura de gobierno antes de que entre en vigor.

→ Changelog: Default enablement of Copilot features for Copilot Business and Enterprise

2. Permisos gestionados para las operaciones de agentes

Ahora puedes controlar de forma centralizada qué operaciones de agentes se bloquean, requieren aprobación humana o pueden continuar sin aviso. Cubre comandos de shell, lecturas y ediciones de archivos y dominios de red, con políticas que los usuarios no pueden debilitar.

→ Changelog: Enterprise-managed permissions for GitHub Copilot agent operations

3. Copilot Code Review: más control empresarial

La revisión de código amplía su gobierno: Copilot puede señalar y, con autorización del administrador, aprobar pull requests; se añaden configuraciones personales a más planes, un ajuste por defecto a nivel empresa, autorresolución y una experiencia de revisión mejorada.

Sources:
→ Changelog: Copilot code review can now approve pull requests
→ Changelog: Copilot code review: more ways to request and configure reviews
→ Changelog: Auto-resolution and analysis updates in Copilot code review
→ Changelog: Copilot code review: an improved review experience

4. Más visibilidad sobre la adopción real

El panel de impacto muestra ahora cuántos usuarios activos usan cada función clave, y las métricas de uso incorporan la actividad de la ventana de agentes de VS Code, las etapas de revisión de pull requests y las personalizaciones de la CLI agéntica. Más datos para dirigir la habilitación.

Sources:
→ Changelog: Copilot impact dashboard now shows feature engagement
→ Changelog: Add VS Code agents to Copilot usage metrics
→ Changelog: Usage metrics API adds pull request review stages
→ Changelog: Agentic CLI customizations now in the usage metrics API

5. Exclusiones de contenido disponibles en la app y la CLI de Copilot

La app de Copilot y la CLI ahora respetan las políticas de exclusión de contenido definidas por administradores de empresa, organización y repositorio. Copilot no usará los archivos excluidos como contexto, protegiendo el código sensible en los flujos agénticos.

→ Changelog: Content exclusions generally available in Copilot app and CLI

6. Modelo por defecto configurable mediante ajustes gestionados

Puedes definir el modelo de Copilot que prefieras como predeterminado para las nuevas conversaciones a través de los ajustes gestionados, e incluso asignar modelos distintos por equipo empresarial. El resto de usuarios hereda tu valor por defecto.

→ Changelog: Enterprise-managed settings support any default model

7. Gobierno del gasto: solicitudes de presupuesto y caducidad

La gestión de costes gana flexibilidad: los miembros que agotan sus créditos pueden solicitar más presupuesto sin salir de ajustes, y tú apruebas, ajustas o deniegas. Además puedes fijar una fecha de caducidad en presupuestos individuales, que GitHub retira automáticamente.

Sources:
→ Changelog: Copilot budget increase requests are generally available
→ Changelog: Set an expiration date for individual user budgets

8. Aislamiento con sandboxes para operaciones de agentes

El aislamiento mediante sandbox se extiende para dar más seguridad a los flujos agénticos: sandboxing local en la app de Copilot y sandbox gestionado por la empresa en Copilot para JetBrains, limitando el alcance de las operaciones sensibles.

Sources:
→ Changelog: Local sandboxing in the GitHub Copilot app
→ Changelog: Enterprise-managed sandbox in Copilot for JetBrains
