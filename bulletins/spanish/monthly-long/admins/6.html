Monthly (Long) #6 · Agosto 2026 · Admins Edition

🎯 El hilo de esta edición

Agosto giró en torno a un mismo eje para quien administra Copilot: gobernanza a escala y visibilidad. Los enterprise managed settings se ampliaron a nuevos clientes y controles (equipos, MCP, marketplaces, JetBrains), la política global de modelos alcanzó disponibilidad general y los paneles de métricas ganaron una lectura de retorno de inversión y un desglose de tokens por modelo. En paralelo, la revisión de código con Copilot maduró con niveles de esfuerzo y nuevas capacidades. El mensaje es claro: más palancas para estandarizar, medir y justificar el despliegue de Copilot en la organización.

⚠️ Atención

  • Próximos cambios en políticas y facturación de Copilot — Fecha: 1 de septiembre de 2026 — Se reabren las altas de Copilot Business y Enterprise con verificación reforzada, convergen varias experiencias en una sola política y la revisión de código pasa a esfuerzo Balanced por defecto. Revise el impacto en sus políticas de empresa.
  • Próxima retirada de MAI-Code-1-Flash — Fecha: 10 de septiembre de 2026 — El modelo se retira en todas las experiencias de Copilot; migre los flujos a MAI-Code-1.1-Flash desde la gestión de modelos.
  • Próxima retirada de GitHub Spark en github.com — Fecha: 31 de agosto de 2026 — Spark deja de aceptar nuevos usuarios y creación de apps.

🚀 Pasa a la acción

  • Estandarice la gobernanza con los enterprise managed settings para equipos, MCP y marketplaces.
  • Defina su política global de modelos antes de que la aplicación gradual concluya el 1 de septiembre.
  • Cuantifique el valor con la sección de retorno de inversión del impact dashboard y la API de métricas de uso.
  • Habilite y ajuste la revisión de código de Copilot para su organización.
  • ¿Preguntas o necesita apoyo? Contacte con su equipo de GitHub, estamos aquí para ayudar.

🏆 Top 8 de actualizaciones del mes

1. Enterprise managed settings más amplios y granulares

La gobernanza centralizada creció en varios frentes: especialización por equipos, listas de permitidos/denegados de servidores MCP, soporte en JetBrains y autoactualización de marketplaces de plugins. Los administradores de grandes empresas pueden estandarizar controles sin cuellos de botella centrales.

Sources:
→ Changelog: Enterprise team specialization for managed settings
→ Changelog: MCP allowlists in enterprise managed settings
→ Changelog: Enterprise managed settings in GitHub Copilot for JetBrains
→ Changelog: Enterprise-managed settings now support autoUpdate for plugin marketplaces

2. Política global de modelos en disponibilidad general

La aplicación de la política por defecto de modelos se despliega gradualmente hasta el 1 de septiembre en Copilot Business y Enterprise. Los modelos nuevos o sin configurar heredan el estado global; los de peso abierto o con retención de datos quedan deshabilitados por defecto.

→ Changelog: Global model policy generally available

3. Retorno de inversión en el impact dashboard

El impact dashboard suma una sección de "retorno de inversión potencial" que conecta el gasto en Copilot con la producción de pull requests. Una herramienta directa para justificar la inversión ante la dirección con datos propios de la organización.

→ Changelog: Copilot impact dashboard adds a return on investment section

4. Métricas de uso con mayor visibilidad

La API de métricas de uso ahora refleja la actividad de agent apps (como Claude y Codex) en los flujos de GitHub, y el informe de uso incorpora un desglose de tokens por modelo (entrada, salida y caché). Más precisión para gobernar consumo y costes.

Sources:
→ Changelog: Copilot usage metrics API adds agent app activity
→ Changelog: Per-model token breakdown in the usage report

5. La revisión de código de Copilot avanza

Los niveles de esfuerzo Lite y Balanced alcanzaron disponibilidad general para ajustar la profundidad al riesgo del cambio. Además, la revisión ahora cubre PRs de bots (incluido el cloud agent) y muy grandes, con razones de resolución para mayor trazabilidad.

Sources:
→ Changelog: Copilot code review effort levels are generally available
→ Changelog: Copilot code review: Resolution reasons and expanded capabilities

6. Nuevos modelos disponibles en Copilot

Agosto amplió el catálogo con Kimi K3, MAI-Code-1.1-Flash, Gemini 3.7 Flash y Grok 4.6. Para administradores, más opciones que gobernar mediante la política de modelos y vigilar en facturación por uso.

Sources:
→ Changelog: Kimi K3 is now available in GitHub Copilot
→ Changelog: MAI-Code-1.1-Flash available in GitHub Copilot
→ Changelog: Gemini 3.7 Flash is now available in GitHub Copilot
→ Changelog: Grok 4.6 is now available in GitHub Copilot

7. Trabajo agéntico compartido en Slack y Teams

La integración de GitHub lleva las capacidades agénticas de Copilot a Slack y Microsoft Teams en vista previa pública. Mencionando a @GitHub, los equipos convierten un hilo en una sesión de agente visible y dirigible por todos, lo que exige atención a permisos e integraciones.

Sources:
→ Changelog: The new GitHub Copilot experience in Slack
→ Changelog: Shared agentic work with GitHub Copilot in Microsoft Teams

8. Agent Plugins 1.0

Ahora se puede construir un plugin una vez y usarlo en todos los clientes de agente compatibles (VS Code, Copilot CLI y la Copilot app), con socios como AWS, Microsoft, OpenAI y Vercel. Un estándar que simplifica la gobernanza de extensiones.

→ Changelog: Agent Plugins 1.0 in VS Code, Copilot CLI, and the Copilot app
