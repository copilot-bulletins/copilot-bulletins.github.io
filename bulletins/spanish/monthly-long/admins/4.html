Monthly (Long) #4 · Junio 2026 · Admins Edition

🎯 El hilo de esta edición

Junio consolida un cambio estructural: con la facturación por uso en vigor desde el día 1, la gestión de Copilot gira ahora en torno al consumo. GitHub ha respondido dotando a los administradores de un control cada vez más granular — presupuestos de créditos por usuario, mayor visibilidad de consumo y adopción, y ajustes gestionados a nivel de empresa. En paralelo, la seguridad del código de agentes y el code review maduran hacia una gobernanza aplicable a escala. Gobernar coste y riesgo es ya tan decisivo como habilitar la adopción.

⚠️ Atención

  • GPT-4.1 deprecated — Efectivo el 1 de junio de 2026 — GPT-4.1 se retiró de todas las experiencias de Copilot; migra a GPT-5.5 y habilítalo en las políticas de modelos de tu empresa.
  • GPT-5.2 and GPT-5.2-Codex deprecated — Efectivo el 5 de junio de 2026 — Ambos modelos se retiraron (GPT-5.2 sigue disponible solo en Copilot code review); usa GPT-5.5 y GPT-5.3-Codex como reemplazos.
  • Upcoming deprecation of Opus 4.6 (fast) — Efectivo el 29 de junio de 2026 — Opus 4.6 (fast) se retira; habilita Opus 4.8 (fast) como sustituto en las políticas de modelos.

🚀 Pasa a la acción

  • Revisa el consumo de créditos de IA por usuario con la API de métricas de uso de Copilot para dimensionar presupuestos antes de que se acumule el gasto.
  • Define presupuestos de créditos de IA por usuario en tus cost centers para controlar el gasto sin configurar límites uno a uno.
  • Configura un runner por defecto a nivel de organización para Copilot code review, que desde el 1 de junio consume minutos de GitHub Actions.
  • ¿Preguntas o necesitas soporte? Contacta con tu equipo de GitHub, estamos aquí para ayudarte.

🏆 Top 8 de actualizaciones del mes

1. La facturación por uso entra en vigor y llegan los controles de coste

Desde el 1 de junio toda la facturación de Copilot se basa en créditos de IA y el code review consume minutos de Actions. Los administradores estrenan presupuestos de créditos por usuario en cost centers, que siguen a cada miembro entre equipos sin límites uno a uno.

Sources:
→ Changelog: Updates to GitHub Copilot billing and plans
→ Changelog: Per-user AI credit budgets available for cost centers

2. Más visibilidad del consumo y la adopción

La API de métricas añade el campo ai_credits_used por usuario y el total de pull requests fusionados por fase de adopción de IA. Visibilidad más granular para dimensionar presupuestos de créditos y focalizar la habilitación según la madurez de cada cohorte.

Sources:
→ Changelog: AI credits consumed per user now in the Copilot usage metrics API
→ Changelog: Track total merges by adoption phase in enterprise and organization reports

3. Configuración gestionada por empresa: gobernanza del cliente más estricta

Nuevos controles aplicados automáticamente a los usuarios de Business y Enterprise: strictKnownMarketplaces limita la instalación de plugins a los marketplaces autorizados y disableBypassPermissionsMode impide saltarse la aprobación de comandos antes de ejecutarlos.

Sources:
→ Changelog: Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI
→ Changelog: Enterprise-managed settings now support bypass permission controls

4. Copilot code review: nuevos controles a nivel de organización

El tipo de runner y el nivel de revisión por defecto ya se configuran a nivel de organización, y el code review respeta las exclusiones de contenido de repositorio, organización y empresa. El nuevo nivel Medium enruta los pull requests complejos a un modelo de mayor razonamiento.

Sources:
→ Changelog: Copilot code review: New configurations and controls
→ Changelog: Copilot code review: Analysis depth and efficiency updates

5. Seguridad para el código generado por agentes

GitHub analiza automáticamente el código de agentes de terceros con CodeQL, la Advisory Database y secret scanning, sin necesidad de licencia de Advanced Security. Además, el comando /security-review de Copilot CLI analiza bajo demanda vulnerabilidades de alto impacto antes de confirmar los cambios.

Sources:
→ Changelog: Security validation for third-party coding agents
→ Changelog: Dedicated security review command now available in Copilot CLI

6. Bring Your Own Key para empresas

Copilot CLI admite modelos BYOK gestionados por la empresa, y la app de GitHub Copilot permite añadir proveedores propios con las claves almacenadas en el llavero local del sistema. Más flexibilidad de modelos manteniendo la configuración bajo control del administrador.

Sources:
→ Changelog: Copilot CLI supports enterprise bring your own key (BYOK) models
→ Changelog: GitHub Copilot app support for BYOK

7. La app de GitHub Copilot alcanza disponibilidad general

La experiencia de escritorio nativa para desarrollo agéntico —sesiones paralelas, canvases, automatizaciones en la nube y BYOK— ya está en disponibilidad general. En Business y Enterprise, los administradores deben habilitar la política de Copilot CLI para que los usuarios accedan.

Sources:
→ Changelog: GitHub Copilot app generally available
→ Blog: GitHub Copilot app: The agent-native desktop experience

8. Nuevos modelos para Business y Enterprise

Claude Sonnet 5 alcanza disponibilidad general y MAI-Code-1-Flash llega a Business y Enterprise, ambos facturados a precio de lista bajo consumo. Los administradores deben habilitar la política de cada modelo en Copilot antes de que los usuarios puedan seleccionarlo.

Sources:
→ Changelog: Claude Sonnet 5 is generally available for GitHub Copilot
→ Changelog: MAI-Code-1-Flash for Copilot Business and Copilot Enterprise
