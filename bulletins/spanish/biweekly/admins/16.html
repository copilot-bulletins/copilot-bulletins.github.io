Biweekly #16 · Del 15 de octubre al 31 de octubre de 2026 · Admins Edition

🎯 El hilo de esta edición

La gobernanza de Copilot pasa de la configuración manual a la gestión programática y centralizada. Durante esta quincena, los controles de licencias, modelos, plugins y políticas por defecto se trasladan a presupuestos, APIs y ajustes gestionados por la empresa. Para los administradores, esto significa menos tareas repetitivas y más visibilidad, pero también la necesidad de revisar las políticas existentes.

⚠️ Atención

  • Upcoming deprecation of selected GitHub Copilot models in mid-November — Deadline: 16 de noviembre de 2026 — Claude Opus 4.8, Claude Opus 5 y GPT-5.6 Terra se retiran. Si desactivaste el valor global por defecto, habilita las alternativas en tus políticas de modelos.

🚀 Pasa a la acción

  • Revisa tu configuración en AI Controls → Copilot → Default policy for new features, apoyándote en la documentación sobre disponibilidad por defecto.
  • Automatiza la gestión de modelos con la API REST de AI controls.
  • Define plugins obligatorios, bloqueados y marketplaces aprobados mediante los ajustes gestionados por la empresa.
  • Familiarízate con el nuevo modelo de consumo consultando la facturación de Copilot para empresas.
  • ¿Preguntas o necesitas ayuda? Contacta con tu equipo de GitHub, estamos aquí para ayudarte.

🏆 Top 5 de actualizaciones

1. Copilot incluido en GitHub Enterprise

Las empresas que trabajan con un equipo de cuentas pueden incluir Copilot para cada usuario con licencia de GitHub Enterprise. Ya no hay que gestionar asientos: el uso de IA se mide desde la primera solicitud contra el presupuesto empresarial, con las políticas y alertas existentes.

→ Changelog: GitHub Enterprise now includes access to GitHub Copilot

2. Control empresarial de plugins, ya disponible

Los administradores pueden exigir o bloquear plugins y restringir la instalación a marketplaces aprobados en VS Code, Copilot CLI y la app de Copilot. Los plugins obligatorios se instalan automáticamente y los ajustes gestionados prevalecen sobre las preferencias de repositorios y usuarios.

→ Changelog: Repository plugin defaults and enterprise plugin controls generally available

3. API de políticas de modelos

Nuevos endpoints GET y PATCH permiten consultar y modificar las políticas de modelos a nivel de empresa, equipos empresariales, agent apps y organizaciones. Ideal para gestionar la disponibilidad de modelos como código y delegar el control donde corresponda.

→ Changelog: Copilot model policy API for enterprise, orgs, and teams

4. Política global por defecto en vigor

Desde el 26 de octubre, las funciones disponibles de forma general que quedaron sin configurar adoptan la política global: Enabled, Disabled o Let organizations decide. Las decisiones explícitas se conservan; conviene verificar el resultado en "Features & clients" y "MCP servers in Copilot".

→ Changelog: Global default for Copilot features generally available

5. Métricas de uso más detalladas

La API de métricas muestra ahora los nombres de skills, agentes personalizados, servidores MCP y plugins internos (hasta 25 entradas), además de un nuevo desglose por cliente, incluidas herramientas externas como OpenCode o Claude Code.
