Biweekly #7 · Del 1 de junio al 14 de junio de 2026 · Admins Edition

🎯 El hilo de esta edición

Esta quincena, GitHub reforzó las palancas de gobernanza para administradores: control del gasto, configuración del code review, validación de seguridad y ajustes gestionados a nivel de empresa. A medida que las capacidades agénticas se generalizan, el foco se desplaza hacia el control —quién consume qué, con qué modelos y bajo qué políticas— para escalar Copilot sin perder visibilidad ni cumplimiento.

⚠️ Atención

  • GPT-4.1 deprecated — Acción requerida — Retirado el 2 de junio en todas las experiencias de Copilot. Los administradores de Copilot Enterprise pueden necesitar habilitar un modelo alternativo en sus políticas; consulte los modelos compatibles.
  • GPT-5.2 and GPT-5.2-Codex deprecated — Acción requerida — Retirados el 5 de junio. Actualice flujos e integraciones y confirme en sus políticas el acceso a modelos compatibles.

🚀 Pasa a la acción

  • Revise la facturación por uso y configure presupuestos por usuario para sus organizaciones con la documentación de facturación y la guía de presupuestos.
  • Establezca y bloquee el runner predeterminado del code review a nivel de organización con la guía de configuración de runners.
  • Confirme que la validación de seguridad está activada en los ajustes del agente en la nube.
  • Defina los estándares de plugins gestionados para su empresa siguiendo la guía de estándares de plugins.
  • ¿Preguntas o necesita ayuda? Contacte con su equipo de GitHub, estamos aquí para ayudarle.

🏆 Top 5 de actualizaciones

1. La facturación por uso llega a todos los planes

La facturación por uso con AI Credits ya aplica a todos los planes de Copilot, con uso mensual incluido. Los presupuestos por usuario llegan a disponibilidad general para organizaciones y empresas, y los administradores pueden fijar un runner predeterminado para el code review.

→ Changelog: Updates to GitHub Copilot billing and plans

2. Nuevos controles de gobernanza en el code review

El code review de Copilot suma controles para administradores: definir y bloquear el runner predeterminado de la organización, respetar las exclusiones de contenido a nivel de repositorio, organización y empresa, y eliminar el límite de caracteres de las instrucciones personalizadas.

→ Changelog: Copilot code review: New configurations and controls

3. Validación de seguridad para agentes de terceros

GitHub analiza ahora el código de agentes de terceros con CodeQL, contrasta las dependencias nuevas con la GitHub Advisory Database y aplica secret scanning. Está activado por defecto según la configuración del repositorio, extendiendo a estos agentes la protección del agente en la nube.

→ Changelog: Security validation for third-party coding agents

4. Plugins gestionados por la empresa en VS Code

Las empresas pueden definir marketplaces de plugins en un settings.json y aplicarlos automáticamente en VS Code y Copilot CLI para usuarios con Copilot Business o Enterprise. Permite estandarizar agentes, skills, hooks y configuraciones MCP, reforzando la gobernanza y acelerando el onboarding.

→ Changelog: Enterprise-managed plugins in VS Code in public preview

5. Gobernanza de preferencias en Copilot Memory

Copilot Memory ya captura preferencias de usuario (estilo, herramientas, convenciones de git) bajo control administrativo. La política existente se aplica también a estas preferencias e incluye exportación para auditoría, borrado masivo, exclusión voluntaria del usuario y aislamiento por entidad de facturación.

→ Changelog: Copilot Memory supports user preferences for Business, Enterprise
