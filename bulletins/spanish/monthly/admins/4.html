Monthly #4 · Junio 2026 · Admins Edition

🎯 El hilo de esta edición

Junio consolidó una prioridad clara para quienes administran Copilot: gobernar la IA a escala. Con la facturación por consumo ya activa, GitHub reforzó los controles de coste, la configuración gestionada a nivel de empresa y las métricas de adopción. El mensaje para los equipos de administración es operativo: menos experimentación aislada y más presupuesto, política y medición bajo control.

⚠️ Atención

  • GPT-4.1 queda obsoleto en Copilot — Obsoleto desde el 1 de junio de 2026 — Habilita la alternativa GPT-5.5 desde las políticas de modelos de tu organización para no bloquear a tus equipos.
  • GPT-5.2 y GPT-5.2-Codex quedan obsoletos — Obsoleto desde el 5 de junio de 2026 — Migra a GPT-5.5 y GPT-5.3-Codex; GPT-5.2 sigue disponible solo en Copilot code review.
  • Opus 4.6 (fast) queda obsoleto — Obsoleto desde el 29 de junio de 2026 — Sustitúyelo por Opus 4.8 (fast) y confirma que la política del modelo esté activa.

🚀 Pasa a la acción

  • Controla el gasto de IA por equipo: define presupuestos de créditos por usuario en tus centros de coste siguiendo la documentación de presupuestos.
  • Refuerza la gobernanza de clientes: desactiva el modo de omisión de permisos ("yolo") con los ajustes gestionados por la empresa y limita los plugins a marketplaces aprobados.
  • Mide la adopción real: revisa el consumo de créditos y las fases de adopción con las métricas de uso de Copilot.
  • Adapta Copilot code review a tu organización: configura runners y exclusiones de contenido con la guía de configuración de runners.
  • ¿Preguntas o necesitas ayuda? Contacta con tu equipo de GitHub, estamos aquí para ayudarte.

🏆 Top 5 de actualizaciones del mes

1. Gobierna el gasto de IA con presupuestos por usuario y métricas de créditos

Con la facturación por consumo activa, los administradores pueden fijar presupuestos de créditos por usuario en centros de coste, y ver el consumo por persona en la API de métricas. El presupuesto sigue a cada usuario sin configurar miles de límites.

Sources:
→ Changelog: Per-user AI credit budgets available for cost centers
→ Changelog: AI credits consumed per user now in the Copilot usage metrics API
→ Changelog: Updates to GitHub Copilot billing and plans

2. Los ajustes gestionados por la empresa suman controles de gobernanza

Los administradores ya pueden desactivar el modo de omisión de permisos ("yolo") y limitar los plugins a marketplaces aprobados en VS Code y Copilot CLI. Junto con los plugins gestionados, estos ajustes se aplican automáticamente a los usuarios de Business y Enterprise.

Sources:
→ Changelog: Enterprise-managed settings now support bypass permission controls
→ Changelog: Enterprise-managed settings now support strictKnownMarketplaces in VS Code and GitHub Copilot CLI
→ Changelog: Enterprise-managed plugins in VS Code in public preview

3. Copilot code review se adapta a los estándares de tu equipo

Nuevos controles llevan code review al nivel de organización: runners configurables, exclusión de contenido, soporte de AGENTS.md, skills y MCP, y un nivel de análisis "medium" para cambios complejos. Además, las mejoras de eficiencia han reducido su coste alrededor de un 20%.

Sources:
→ Changelog: Shape Copilot code review around your team
→ Changelog: Copilot code review: New configurations and controls
→ Changelog: Copilot code review: AGENTS.md support and UI improvements
→ Changelog: Copilot code review: Analysis depth and efficiency updates

4. Métricas de adopción más completas y accionables

Los informes de uso ahora incluyen usuarios activos detectados por telemetría de servidor, no solo del cliente, y muestran el total de pull requests fusionadas por fase de adopción. Los administradores obtienen una imagen más fiel del retorno y del progreso de sus equipos.

Sources:
→ Changelog: Copilot usage metrics now include more of your active users
→ Changelog: Track total merges by adoption phase in enterprise and organization reports

5. La validación de seguridad se extiende a los agentes de terceros

El código generado por agentes de terceros (Claude, OpenAI Codex) recibe ahora la misma validación automática que el agente de Copilot: CodeQL, revisión de dependencias y secret scanning. En paralelo, Copilot CLI estrena el comando /security-review para detectar vulnerabilidades antes de producción.

Sources:
→ Changelog: Security validation for third-party coding agents
→ Changelog: Dedicated security review command now available in Copilot CLI
